# StockLoop PRD — AI 한국주식 상승 본질 분석·검증·진화 엔진

- **버전**: v1.0 (Draft → 확정)
- **작성 기준**: `prd_draft.md` v3 + `/grill-yourself` 설계 확정 + `/grill-review`(auto) 수정 반영
- **최종 갱신**: 2026-06-20
- **상태**: 구현 착수 가능 (Blocker 2건 해소 완료)

---

## 0. 한 줄 정의

상승 가능성이 높은 한국 주식을 찾는 데서 끝나지 않고, **상승의 본질(수급·기대·근거·구조·지속성)을 점수화·설명하고, 추천을 가상매수로 기록·검증하며, 실패를 태깅해 엔진을 버전 진화시키는 폐루프(loop) 투자 판단 시스템**.

---

## 1. 배경과 문제 정의

투자자는 종목은 보지만 구조는 보지 못한다. 차트는 보되 왜 오르는지 모르고, 추천은 받되 그 추천이 맞았는지 추적하지 않는다. 결국 두 가지가 빠져 있다.

1. **왜 이 종목이 오를 수 있는지** 구조적으로 설명되지 않는다.
2. 추천 후 **결과를 데이터로 검증하고 반성하는 체계**가 없다.

StockLoop은 이 두 결손을 "점수 엔진 + 검증 루프 + 버전 진화"로 메운다.

### 상승의 본질 5단계 (점수 엔진의 철학적 기반)

| 단계 | 의미 |
|---|---|
| 수급 | 주가는 결국 매수 수요가 더 강할 때 오른다 |
| 기대 | 수급은 "더 오를 것 같다"는 기대를 먹고 들어온다 |
| 근거 | 기대는 뉴스·공시·실적·수주·정책으로 강화된다 |
| 구조 | 근거가 산업·정책·거시와 연결되면 구조적 상승이 된다 |
| 지속성 | 결국 중요한 건 이 상승이 얼마나 지속되느냐다 |

## 2. 사용자 (v1 범위)

| 역할 | v1 사용 여부 | 비고 |
|---|---|---|
| 현준 (전략·운영 책임) | O | 1차 사용자 |
| 내부 팀원 (데이터 확인·실패 분석) | O | 1차 사용자 |
| 일반 사용자 | X (Phase 3 이후) | 검증·법적 정합 후 공개 |
| 개발자 | O | 수집·저장·로직·관리자 기능 구현 |

> **결정 (Q2/Q3)**: v1은 **운영자용 웹 대시보드**로 좁힌다. 검증되지 않은 엔진을 일반 사용자에게 먼저 노출하지 않는다.

### 플랫폼 정책 (수정 반영 — Advisory Q3)

- v1은 운영자 검증용 **웹 대시보드**. 단 **API-first**로 설계하여 동일 백엔드를 향후 모바일 앱이 그대로 소비한다.
- **가정/리스크**: 사업 목표상 2026-08 앱스토어 런칭과의 우선순위는 별도 사업 결정 사항. 본 PRD는 "엔진+운영자 웹"을 선행 산출물로 정의하며, 모바일 일정 충돌 여부는 사업측과 확정해야 한다.

## 3. 제품 범위 — 3단계 페이즈

| Phase | 범위 | 한 줄 |
|---|---|---|
| **Phase 1 (MVP)** | 데이터 수집 → 점수 계산 → 추천 → 자동 가상매수 → KPI 대시보드 + **과거 백테스트 부트스트랩** | "보여준다" |
| **Phase 2** | 성과 검증(7/30/90/365일) → 성공·실패 판정 → 실패 태깅·메모, **실시간 급등주 스캐너용 장중 데이터 소스 결정** | "검증한다" |
| **Phase 3** | 엔진 버전 관리 → 진화(가중치 조정) → 버전별 성과 비교, 일반 사용자 공개 검토 | "학습한다" |

> 트렌드 연쇄 모듈·소비자 모바일 앱은 Phase 2~3 이후 별도 트랙.

## 4. 데이터 소스 (확정)

| 데이터 | 소스 | 결정 근거 / 정책 |
|---|---|---|
| 시세 (OHLCV, 거래대금) | **pykrx** (KRX) | 무료, 일봉 중심. **실시간 틱·호가 미제공** → 급등주 실시간 스캐너는 Phase 2로 분리 |
| 공시 | **OpenDART API** | 무료 API 키. 유증·자사주·실적·수주·주요 경영이슈 |
| 검색 관심도 | **pytrends** (Google Trends) | 비공식 → **일배치 캐싱 + 재시도 + 결손 시 해당 신호 가중치 0 처리**(graceful degradation) |
| 뉴스 | **네이버 검색 API (뉴스)** | **공식 API로 확정, 일반 페이지 크롤링 금지** (ToS·차단 리스크 제거) |
| 메타데이터 | pykrx + DART 통합 | 종목코드·업종·섹터·시총·시장구분 |

### 스캔 유니버스 (확정 — Q-new-topN)

- 대상: KOSPI + KOSDAQ 전체
- 유동성 필터: **직전 20거래일 평균 거래대금 하위 30% 제외**
- 일 추천 개수: **상위 N = 20개**

## 5. 점수 엔진 — `total_force_score`

5개 하위 점수의 **가중합(0~100 정규화)**. 가중치는 코드 상수가 아니라 `engine_versions` 테이블에 버전별로 저장(불변 이력).

### 하위 점수 산출식 (확정 — Blocker Q5 해소)

| 하위 점수 | 산출 방법 | 입력 |
|---|---|---|
| 가격 모멘텀 | 규칙 기반 정량식 (N일 수익률·이평 이격·신고가 근접도) | pykrx 일봉 |
| 거래량 검증 | 규칙 기반 정량식 (거래대금 급증 배수, 평소 대비 z-score) | pykrx 거래대금 |
| 뉴스 연관성 | 종목·키워드 매칭 **빈도 점수** | 네이버 뉴스 API |
| 뉴스 감성 | **Claude API 분류** (호재/악재/중립) — 폴백: 한국어 감성 사전 | 네이버 뉴스 API |
| 추가 상승 여력 | 규칙 기반 정량식 (52주 고점 대비 여력, 과열 차감) | pykrx 일봉 |

- 추천 레코드에는 **사용된 `engine_version`을 함께 저장**(재현성).
- 가중치 초기값은 v1.0 엔진 버전에 명시하고, 진화 시 새 행을 추가한다(기존 행 불변).

### 추천 사유 생성

- **Claude API** (`claude-opus-4-8` 또는 `claude-sonnet-4-6`)로 구조화 신호 → 자연어 설명 문장 생성.
- 메인 화면 문구는 짧고 즉시 이해 가능하게, 상세는 깊게 (프로토타입 "쉽게 풀어내기" 원칙 계승).

## 6. 추천·검증 폐루프 (일배치)

> **데이터 cadence 정책 (Blocker Q13 해소)**: v1은 **2-tier**.
> (1) **장 마감 후 일배치** — 추천·가상매수·검증.
> (2) **급등주 스캐너** — v1에서는 "**전일 일봉 기반 모멘텀 스캐너**"로 한정. 실시간 틱/분봉 스캐너는 Phase 2 데이터 소스 결정으로 이관.

장 마감 후 일배치 흐름:

1. 전체 시장 스캔 → 원천 데이터 수집·저장
2. 유동성/리스크 필터로 후보 압축
3. `total_force_score` 계산 (현재 활성 엔진 버전)
4. Claude API로 추천 사유 문장 생성
5. 상위 N(=20)개 추천 확정 + 규칙 기반 리스크 등급 부여
6. **자동 가상매수**: 추천 종목 전부, 당일 종가 기준 진입가 기록 (선택 편향 제거)
7. 보유 기간별 성과 측정 (7/30/90/365일, 최대상승·최대낙폭)
8. 성공/실패 판정 (아래 기준)
9. 실패 시 실패 태그·메모 저장
10. 성과 저하/드리프트 경고 → 버전 개선 결정 (운영자 트리거 반자동)

### 성공/실패 판정 기준 (확정 — Advisory Q15)

- **성공**: 보유기간 종료 시 **+5% 이상** (옵션: 동기간 시장 대비 초과수익 병기)
- **실패**: **-5% 이하** 또는 손절 룰 발동
- **보합**: 그 사이
- 기간별(7/30/90/365일) 동일 임계 적용

### 과거 백테스트 부트스트랩 (추가 — Advisory Q-new-backtest)

- 가상매수는 전향적(forward)이라 1년 수익률·"최근 7일 성공률" KPI·Phase 3 진화가 누적 데이터를 기다려야 한다.
- 이를 해소하기 위해 **pykrx 과거 일봉으로 과거 N개월 백테스트 경로를 v1에 포함**, 런칭 직후부터 엔진 성과를 평가·진화할 수 있게 한다.
- (참고: `project_wise` 프로토타입에 이미 백테스트 탭(180거래일·9회 리밸런싱)이 존재 → 구조 참고 가능)

## 7. 리스크 등급 (확정 — Advisory Q16)

모든 추천에 리스크 등급을 **병행 노출**(상승 가능성만 말하지 않는다).

| 등급 | 룰 |
|---|---|
| **High** | 52주 고점 대비 +X% 이내 추격 **AND** 거래량 급증 동반 |
| **Medium** | 위 두 조건 중 하나 |
| **Low** | 해당 없음 |

> 구체 임계값(X% 등)은 PRD 부록 표로 관리하며 엔진 버전과 함께 조정한다.

## 10. 진화(Evolution) — 무엇을 기준으로, 무엇을 바꾸나

### 진화 트리거 (운영자 트리거 반자동)

경고는 자동 감지하되 가중치 변경은 사람이 승인(초기 과적합 방지).

- **성능 저하**: 최근 8주 성공률 하락 / 평균 수익률 악화 / 최대 낙폭 확대 / 실패 태그 반복 / 특정 섹터 실패 집중
- **데이터 드리프트**: 뉴스·검색량 패턴 변화 / 지표 분포 변화 / 과거 유효 신호의 성과 약화
- **수동**: 운영자 판단

### 개선 대상

- 데이터: 누락 뉴스 보완, 공시 분류·섹터 매핑 수정, 키워드 사전 보강
- 점수: 뉴스/거래량 가중치 조정, 과열 차감 강화, 기간별 점수 분리
- 검증: 슬리피지 반영, 시장 대비 초과성과 비교, 최대 낙폭 반영 확대
- 운영: 주간 리뷰·월간 업그레이드 회의 정례화, 실패 태그 정규화

## 13. 개발자 구현 체크리스트

1. 데이터 수집 구조 (pykrx / OpenDART / pytrends / 네이버 검색 API)
2. 원천 데이터 저장 구조 (raw_* 테이블, 추천 당시 상태 보존)
3. 점수 엔진 (5개 하위 산출식 + 가중합 + engine_version 스냅샷)
4. 추천 사유 생성 (Claude API)
5. 자동 가상매수 + 성과 추적 (7/30/90/365일)
6. 성공/실패 판정 + 실패 태깅
7. 과거 백테스트 부트스트랩
8. 엔진 버전 관리 + 가중치 시각화
9. KPI 대시보드 + 모듈 기반 UI
10. 리스크 등급 병행 노출
11. 법적 면책 문구

## 14. 결론

StockLoop은 **"보기 좋은 분석 앱"과 "실제로 학습하는 검증 시스템"이 합쳐진 형태**로 완성한다.
프로토타입의 UI 방향성·모듈 구조는 살리고, 초안에 없던 **데이터·기록·검증·진화** 구조를 붙여 현준만의 진짜 투자 엔진으로 만든다.

상승의 이유를 구조적으로 읽고 → 쉽게 설명하고 → 성과를 검증하며 → 실패를 개선으로 연결하고 → 다음 버전을 더 좋아지게 만드는 것. 이것이 목표다.
