## 1. 배경 (Background)

개인 투자자가 주식에서 가장 어려워하는 건 종목 고르기 자체가 아니라 **두 가지를 모른다는 것**이다 (사장님 2차 글 '사고트리'):

1. 지금 시장을 움직이는 **큰 흐름(이야기/테마)이 무엇인지**
2. 내가 가진 종목이 그 흐름 안에서 **어디쯤(초반/중간/끝물) 있는지**

그래서 뉴스·유튜브·카톡방에 **그때그때 휘둘리며 뒤늦게 쫓아 들어가는** 경우가 많다. 야호는 "하루치 뉴스"가 아니라 **"큰 그림(이야기 흐름)을 한눈에 보여주는 나침반"**으로 이 문제를 푼다. MVP는 위 두 질문을 모두 건드린다 — 큰 흐름(이야기 지도)과 "내 종목이 어느 이야기에 있나"(읽기 전용 역조회, §6.4).

### 1.1 개념적 기원 (사장님 이론)

야호의 엔진은 새로운 이론이 아니라 **사장님이 평소 말하던 모델**에서 출발한다.

- 대표주 → 2·3등 → 부품주로 번지는 **도미노 파동(FOMO 확산)** = 야호의 '이야기 확산 단계'
- 추세가 한 방향으로 이어지는 **우상향 법칙** = 야호의 '추세 강도'

> 야호는 사장님 투자 프레임워크의 **"서사(narrative)·뉴스 추세" 관점을 일반인용 독립 제품으로 떼어낸 것**이다. (개념적 기원이며, 다른 제품과 인프라를 공유한다는 뜻은 아니다 — 독립 제품.)

### 1.2 노리는 비효율은 실재한다

사장님이 일반인 언어로 적은 두 현상은 학계에서 검증된 시장 비효율과 일치한다 — 야호가 겨냥하는 빈틈이 공상이 아니라는 근거다.

- "좋은 소식에도 처음엔 덜 오르고 천천히 더 오른다" → **PEAD(실적발표 후 주가 표류)**
- "이익은 빨리 팔고 손실은 오래 들고 있다" → **처분효과(disposition effect)**

### 1.3 시장 검증

"종목보다 테마를 먼저 보여준다"는 방향은 이미 검증된 개념이다(2차 글 '시장조사트리'). 잘 나가는 테마 앱들은 테마 → 종목 순으로 노출하고, 기관용 대시보드는 수십~수백 테마를 색으로 지도화한다. **야호의 차별점은 "기관이 아니라 일반인"** — 정보량을 줄이고, 친숙한 이름과 색·한 줄로 메시지를 전한다.

## 2. 목표 / 비목표

### 2.1 목표 (Goals)
- **G1.** 지금 시장의 이야기(테마)가 **생애주기 어디쯤(초반/중간/끝물)**인지 신호등으로 한눈에 보여준다.
- **G2.** 사용자가 "뭐가 막 시작이고, 뭐가 한창이고, 뭐가 위험한지" 세 질문에 즉답을 얻게 한다. (단, '막 시작'은 §3·§6.2의 정직 포지셔닝을 따른다.)
- **G3.** "내가 가진/관심 있는 종목이 어느 이야기에, 그 이야기가 지금 어느 단계인지"를 알려준다(읽기 전용 역조회, §6.4).
- **G4.** 정답을 찍어주지 않고 **사용자가 자기 머리로 판단할 여지**를 남긴다("나침반").

### 2.2 비목표 (Non-Goals)
- **N1.** 종목 추천·매수/매도 지시·목표가 제시 (정보·교육 전용, §9).
- **N2.** "시작을 정확히 맞히는" 예언 (후행 데이터의 한계, §3 → '단계 판별기'로 포지셔닝).
- **N3.** 실시간 틱 단위 분석·HTS급 차트 (하루 1회 배치, §5).
- **N4.** **사주·운세·성향 결합** (야호는 사주와 무관한 독립 제품).
- **N5.** **전체 종목 검색 UX**(한 줄 코멘트·관심목록·검색 고도화)·로테이션·개인화 알림 (Phase 2). 단, **읽기 전용 종목→테마 역조회는 MVP 포함**(§6.4). 커뮤니티/유튜브 신호·ML 고도화 (Phase 3).

## 3. 설계 원칙 (Design Principles)

1. **나침반이지 정답기가 아니다** — "이 종목 사세요"가 아니라 "지금 시장 이야기 흐름은 이렇습니다". 사용자의 사고 여지를 보존한다(2차 글 '참모트리'의 핵심 차별점).
2. **단계 판별기이지 시작 포착기가 아니다** — 야호가 보는 신호(뉴스 수·검색량·거래량)는 전부 관심이 *붙은 뒤* 증가하는 후행 지표다. 그래서 "시작을 맞힌다"고 약속하지 않고 **"지금 몇 단계인지 판별"**한다. **'막 시작'은 "지금 사라"가 아니라 "관심이 빨라지는 중(리드타임 미보장)"**으로 표현하고, 가속도→가격 리드타임을 출시 후 검증한다(§14).
3. **절대량이 아니라 가속도/이례성** — "기사가 많다"가 아니라 "갑자기 빨라졌다"를 본다(평소 대비 z-score). 단, **신규(무이력) 테마는 베이스라인이 없으므로 cold-start 규칙**(§10.2)으로 처리.
4. **색 = 단계** — 초록/노랑/빨강은 '기회/위험'이 아니라 **생애주기 단계**를 뜻한다(§5.3). 의미를 일관되게 고정.
5. **점진적 공개(progressive disclosure)** — 첫 화면은 색·단계·화살표만. 숫자(%)·그래프·긴 글은 카드를 탭한 상세에서만.
6. **건강한 심리** — 자극어(위험·폭락) 금지, "끝물 가능성·추격 주의" 사용. **비대칭 히스테리시스**(끝물 경고는 빠르게, 그 외 단계 변경은 느리게)로 적시성과 안정성을 동시에. 하루 1회 갱신 + 큰 뉴스만 특별 갱신.
7. **정보·교육 톤** — 추천·지시 표현 금지. 전 화면 면책. 규제 리스크를 코드와 문구에 내장(§9).

## 4. 제품 전략 / 단계화 로드맵

야호는 사주앱과 무관한 **독립 standalone 제품**이다. 출시 일정은 독립 트랙이며, 사주앱의 8월 일정에 묶이지 않는다(MVP를 작게 가져간다).

| 단계 | 범위 |
|---|---|
| **Phase 1 (MVP)** | 큐레이션 테마 8~12개 + **홈(이야기 지도 + 오늘 한 줄 요약)** + **3섹션(막시작/한창/조심)** + **이야기 상세** + **읽기 전용 종목→테마 역조회(§6.4)** + 일 1회 배치 + 규칙 기반 단계 판정. |
| **Phase 2** | **전체 종목 검색**(한 줄 코멘트·검색 UX·관심목록) + **로테이션(돈 흐름)** + **개인화 알림**(보유·관심 종목 대상). |
| **Phase 3** | 커뮤니티/유튜브 신호 통합 + 단계 판정 **ML 고도화**. |

> **MVP 근거:** 테마-측 신호등이 핵심 가설(이야기 단계 판별)을 가장 작게 증명한다. 여기에 **읽기 전용 종목→테마 역조회**를 더한 이유는, 그 데이터(N:N 매핑)가 이미 이야기 상세의 종목 목록을 채우는 데 필요해 **역인덱스 한 번이면 거의 공짜**이고, §1의 두 번째 핵심 질문("내 종목이 어디쯤")을 충족해 개인 사용자의 재방문 훅이 되기 때문이다. 한 줄 코멘트·검색 고도화·관심목록은 판단·규제 부담이 있어 Phase 2.

## 5. 시스템 아키텍처

### 5.1 기술 스택

| 구성요소 | 선택 | 비고 |
|---|---|---|
| 프론트 | **웹뷰 우선(웹) → 네이티브 셸로 감싸기** | |
| 백엔드 | **일 1회 배치 파이프라인 + 읽기 API** | 실시간 인프라 불필요(하루 1회 갱신) |
| 단계 판정 | **규칙 기반 엔진**(설명 가능) | LLM 아님 — 재현·규제 방어 |
| 분류·요약 | **LLM(Claude)** | 배치 호출 + 캐싱으로 비용 통제 |
| 저장소 | 테마·종목·시계열·판정 결과 + **종목→테마 역인덱스** 캐시 (RDB) | 일 1회 스냅샷 |

### 5.2 데이터 파이프라인 (하루 1회 = 장 마감 후, 큰 뉴스 시 특별 갱신)

```
[수집]  한국 뉴스(네이버 뉴스/언론 RSS) · 시세·거래량(KRX/증권사 API) · 검색 트렌드(네이버 데이터랩)
   │
[정제]  종목명·티커 정규화, 중복 기사 dedup, 유의미 뉴스 필터
   │
[매핑]  LLM이 뉴스→테마 분류 + 종목 추출/후보 제안 → 사람 검수(하이브리드, N:N)
   │       ├─ 매핑 QA 운영 규칙 적용(§5.5)
   │       └─ 종목→테마 역인덱스 생성(§6.4 역조회용)
   │
[판정]  규칙 엔진: 관심 가속도(z-score) + 추세 강도 + 뉴스동반상승비율 → 단계(초/중/끝물) + 색 (§10)
   │       ├─ cold-start: 무이력 테마는 전체시장/타 테마 중앙값 베이스라인 또는 '신규 관측' 라벨
   │       └─ 비대칭 히스테리시스: 끝물(빨강)은 빠르게 진입, 그 외 단계 변경은 느리게
   │
[생성]  LLM: 이야기 2~3줄 요약 · "오늘 시장 한 줄 요약" (종목 한 줄 코멘트는 Phase 2)
   │
[캐시]  스냅샷 저장 → 읽기 API → 웹뷰
```

### 5.3 신호등 ↔ 단계 정의 (고정)

| 색 | 단계 | 의미 | 문구 예 |
|---|---|---|---|
| 초록 | **초반** | 관심이 막 붙기 시작(가속 시작) | "관심 가져볼 만한 이야기" |
| 노랑 | **중간** | 추세 확산·이미 많이 오름 | "이미 진행 중, 신중하게" |
| 빨강 | **끝물 가능성** | 과열·관심 정점·뉴스 없는 급등 증가 | "끝물 가능성, 추격 주의" |

> 색은 **단계**를 의미하며 매수/매도 신호가 아니다. 자극어(위험·폭락) 금지.

### 5.4 테마 모델 (하이브리드 매핑)
- **초기 핵심 테마 8~12개**를 **수작업 큐레이션**(대표주 3~5 + 따라가는 종목 몇 개). **평면 목록(카테고리 계층 없음).**
- **LLM이 뉴스에서 종목 추출·신규 후보 제안 → 사람이 검수**(순수 자동은 부정확, 순수 수작업은 확장 불가).
- **다중 테마(N:N) 허용** — 한 종목이 여러 이야기에 속할 수 있음. 이 매핑으로 **종목→테마 역인덱스**를 만들어 §6.4 역조회에 사용.
- **테마 이름은 뉴스 친숙어 그대로**: `AI 반도체` `로봇` `방산` `조선` `2차전지` `바이오` `원전` `자동차/전장` `엔터` `우주` 등. 추상어(`AI 인프라`·`플랫폼 전환`) 금지.
- **신규 테마 패스트트랙 온보딩(grill-review A6/2차):** LLM이 기존 8~12개에 안 잡히는 **떠오르는 뉴스 클러스터**를 감지하면 '후보 테마'로 올리고 **우선 검수**한다. '막 시작' 섹션의 신선도가 정기 QA 주기(주 1회)에 묶이지 않도록, 후보 테마는 검수 통과 즉시 '신규 관측' 라벨로 노출 가능.

### 5.5 매핑 QA 운영 (grill-review A5)
종목-테마 매핑은 모든 하류(단계 판정·화면·역조회)를 좌우하므로 운영 규칙을 명문화한다.
- **검수 담당·주기**: 정기 검수(예: 주 1회) + **신규 테마 후보 발생 시 즉시(패스트트랙, §5.4)**.
- **어드민 툴**: 매핑·테마 후보 추가/삭제/검수 상태를 관리하는 내부 화면.
- **오분류 정확도 임계**: 표본 검수 정확도가 임계 미달이면 LLM 후보 신뢰도를 낮추고 재큐레이션.

## 6. 화면 명세 (Phase 1, 4화면)

### 6.1 홈 — 오늘 한 줄 요약 + 이야기 지도
- **맨 위:** 오늘 시장 한 줄 요약. 예) "오늘은 로봇이 새로 떠오르고, AI 반도체는 계속 강하며, 방산은 열기가 줄어드는 중입니다."
- **가운데:** 이야기 지도 — 테마 카드 여러 개. 카드 = **이름 + 색 + 단계 꼬리표 + 화살표(상승/하강/유지)**. (숫자·그래프 없음)
- *돈이 옮겨가는 방향(로테이션)은 Phase 2.*

### 6.2 막 시작 / 한창 / 조심 — 3섹션
- **막 시작:** **"관심이 빨라지는 중"**인 이야기 후보(신규 테마 패스트트랙 포함). ※ "지금 사라"가 아니라 관심 가속 신호이며 **리드타임을 보장하지 않음**을 문구로 명시(§3).
- **한창:** 요즘 시장 중심의 이야기(중간 단계).
- **조심:** 너무 올라 새 진입이 위험할 수 있는 이야기(끝물 가능성).
- 각 이야기에 `초반 / 중간 / 끝물 가능성` 꼬리표.

### 6.3 이야기 상세
- 이 이야기가 뭔지 **2~3줄 설명**(LLM 생성).
- 현재 단계(초반/중간/끝물) + 신호등.
- 대표 종목 3개 + 따라가는 종목 몇 개.
- 과거 비슷한 패턴에서 어떤 일이 있었는지 **한 줄**(정보성, 수익 보장·예측 표현 금지, §9).
- **숫자(%)·그래프·긴 글은 이 상세에서만** 노출(progressive disclosure).

### 6.4 종목→테마 역조회 (읽기 전용, grill-review A2/2차)
- 종목명/티커 입력 → **그 종목이 얽힌 이야기(테마) 목록 + 각 테마의 현재 단계(신호등)**만 표시.
- §5.4의 N:N 역인덱스를 그대로 사용(추가 데이터 불필요).
- **MVP 범위 한정:** 한 줄 코멘트(유지/비중 줄이기 등 판단성 문구)·검색 자동완성·관심목록·알림은 **넣지 않는다**(Phase 2). 이는 §9 규제(판단성 표현 회피)와도 일치.

## 7. 기능 요구사항 (Functional Requirements)

- **FR-1 이야기 지도(홈)** — 핵심 테마 8~12개를 색·단계·화살표 카드로 표시 + 오늘 한 줄 요약.
- **FR-2 3섹션 분류** — 모든 테마를 막 시작/한창/조심으로 자동 배치(단계 판정 결과 기반). '막 시작'은 §6.2 정직 문구 + 신규 테마 패스트트랙 반영.
- **FR-3 이야기 상세** — 설명 2~3줄 + 단계 + 대표/추종 종목 + 과거 패턴 한 줄.
- **FR-4 종목→테마 역조회(읽기 전용)** — 종목 입력 시 얽힌 테마 목록 + 각 단계 표시(§6.4). 판단성 코멘트·검색 고도화 없음.
- **FR-5 단계 판정 엔진** — 관심 가속도 + 추세 강도 + 뉴스동반상승비율로 초반/중간/끝물 + 색 산출(§10). **cold-start + 비대칭 히스테리시스 + 끝물 정점-감쇠 규칙** 포함.
- **FR-6 하이브리드 테마 매핑 + QA + 패스트트랙** — 수작업 큐레이션 + LLM 추출/제안 + 사람 검수(N:N) + 신규 테마 후보 즉시 검수(§5.4–5.5).
- **FR-7 LLM 생성물** — 이야기 요약·오늘 한 줄 요약(배치+캐싱).
- **FR-8 일 1회 갱신 + 특별 갱신** — 장 마감 후 정규 갱신, 큰 뉴스 시에만 추가 배치.
- **FR-9 면책 상시 표기** — 전 화면 "투자 정보 제공이며 자문·권유 아님, 책임은 본인"(§9).
- **(Phase 2)** 전체 종목 검색·코멘트, 로테이션 표시, 개인화 알림.

## 8. 비기능 요구사항 (Non-Functional Requirements)

- **NFR-1 단순성** — 첫 화면 정보 최소(progressive disclosure). 비전문가가 색·한 줄로 즉시 이해.
- **NFR-2 설명 가능성** — 단계 판정은 규칙 기반이라 "왜 이 색인지" 설명 가능(블랙박스 ML 금지).
- **NFR-3 심리 안정성** — 비대칭 히스테리시스, 하루 1회 갱신, 자극어 회피.
- **NFR-4 비용 예측성** — LLM은 배치(하루 1회 + 큰 뉴스) + 캐싱으로 호출 통제. 테마 8~12개 한정.
- **NFR-5 한국어 처리** — 한국 뉴스·검색어 기준. LLM(Claude) 한국어 그대로.
- **NFR-6 데이터 출처 준법** — 뉴스/시세/검색 데이터의 라이선스·ToS 준수(§15).

## 9. 규제 / 법무

- 야호는 **정보·교육 전용**이며 종목 추천·매매 지시·목표가 제시를 하지 않는다.
- 단계·색은 **시장 상태 정보**이지 매수/매도 신호가 아니다. 자극어(위험·폭락) 금지 → "끝물 가능성·추격 주의".
- **종목→테마 역조회(§6.4)는 사실 표시만**(얽힌 테마 + 단계). 판단성 한 줄 코멘트는 Phase 2로 미뤄 규제 노출을 줄인다.
- 전 화면에 면책: **"투자 정보 제공 서비스이며 투자 자문·권유가 아닙니다. 투자 판단과 책임은 본인에게 있습니다."**
- 과거 패턴·백테스트는 **수익 보장·예측으로 표현 금지**, 정보성 사례로만(§10.3).
- **★법률 검토 게이트(출시 전 필수):**
  - 테마 신호등·3섹션·종목→테마 역조회 표시 형태가 자본시장법상 **유사투자자문/투자자문업**에 해당하는지.
  - **(Phase 2) 개인화 알림·종목 코멘트** — 보유·관심 종목 대상 '추격 주의' 푸시나 '비중 줄이기' 코멘트는 개별성이 높아 일반 면책으로 안 덮일 수 있음 → **시장 일반 정보와 분리해 별도 검토**(grill-review A4).

## 10. 단계 판정 로직 (MVP, 규칙 기반)

> 설명 가능·재현 가능한 단순 규칙. ML 블랙박스 금지. 가중치·임계값은 출시 후 보정(과적합 경계).

### 10.1 입력 (테마 단위, 일 1회 산출)
1. **관심 가속도 A** — 뉴스 건수·검색 트렌드의 *증가 속도*를 평소 대비 표준화(z-score). "많다"가 아니라 "갑자기 빨라졌다".
2. **추세 강도 T** — 1주·1달 수익률의 방향과 크기.
3. **뉴스 동반 상승 비율 N** — 상승일 중 유의미 뉴스가 있던 비율 vs 뉴스 없는 급등 비율.

### 10.2 단계 매핑 + 보정
| 단계(색) | 특징 |
|---|---|
| 초반(초록) | A 급상승 *시작* + T 양(+)이나 누적 작음 + 상승이 주로 뉴스 동반 |
| 중간(노랑) | A 높게 지속 + T 강한 상승 누적 + 거래량 증가 |
| 끝물(빨강) | A 정점-감쇠 + T 과도 누적 + 뉴스 없는 급등 비율↑ |

- 세 입력을 가중 점수화 → 임계값으로 3단계 배정.
- **cold-start (A1, v2.1 정정):** 자체 이력이 부족한 신규 테마는 z-score를 적용하지 않고, **전체시장/타 테마의 중앙값 베이스라인**으로 대체하거나 충분한 이력이 쌓이기 전까지 **'신규 관측' 라벨**로 표시한다. (테마 모델은 평면이므로 '상위 카테고리' 베이스라인은 쓰지 않는다.)
- **비대칭 히스테리시스 (A2):** 끝물(빨강·추격 주의)은 조건 충족 시 빠르게 진입, 그 외 단계 변경은 연속 N일 충족 시에만 반영.
- **끝물 정점-감쇠 탐지 (A-2차/D14):** 관심 가속도 A가 **국소 최대(정점) 후 k일 연속 하락**하면 '둔화'로 판정해 끝물 신호에 반영. 초기 k는 잠정값, 출시 후 검증·보정(노이즈 큰 일간 데이터 고려).

### 10.3 사후확신·과적합 방어
- "초반/끝물"은 사후엔 명확하지만 실시간엔 불확실 — UI는 항상 **가능성/후보**로 표현.
- 백테스트는 **내부 검증(out-of-sample / walk-forward) 한정**, 화려한 수익률을 UI에 광고하지 않는다.
- 생존편향 경계: 사라진 테마도 학습 표본에 포함.

| **종목-테마 매핑 부정확** | 하이브리드 + N:N + **매핑 QA 운영**(§5.5) + 테마 8~12개로 범위 한정 |
| **규제(투자권유 해석)** | 정보·교육 톤 + 면책 상시 + 법률 검토 게이트, 역조회는 사실만·코멘트/개인화 알림은 Phase 2 분리 검토 |
| **심리 교란(잦은 색 변동·공포)** | 비대칭 히스테리시스 + 하루 1회 갱신 + 자극어 회피 |
| **정보 과부하** | progressive disclosure(첫 화면 카드만) |
| **LLM 비용 폭주** | 배치+캐싱 + 테마 수 한정 + 판정은 규칙(LLM 분리) |
| **사용자 획득**(사주 퍼널 상실) | 초기 채널 1개로 시작(테마 요약 콘텐츠 SEO/숏폼) + 본격 GTM 별도 plan(§15) |
| **데이터 출처 ToS/라이선스** | 합법 API 우선(네이버/KRX), 크롤링 정책 사전 검토(§15) |
