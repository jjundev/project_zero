## 0. 표시 원칙 (Display Principles) — 흔들리지 않는 골격

대상은 **55세 비기술 투자자**(NFR-7). 모든 섹션은 아래 3단 위계를 따른다 — **기본은 단순하게, 깊이는 펼쳐서.**

| 위계 | 노출 시점 | 요소 |
|---|---|---|
| **1차 (상시)** | 항상 | 질문 원문 · **이 질문의 핵심 쟁점 1줄** · 현재 단계 · 알맹이(있으면) · 한도 임박 경고(80·100%, 예외 승격) |
| **2차 (단계 진입 시)** | 해당 단계 패널에서 | 근거 카드 · 토론 전사 · 왜 체인 |
| **3차 (요청 시 숨김)** | 클릭해야 | 비용 *상세*(호출수·토큰·월 사용) · 모델명·연결 상세 · 텔레메트리 |

- **P1 한 번에 하나** — 현재 턴은 활성 단계 패널 1개만. 이전 턴은 기본 접힘(§4).
- **P2 기술 용어 비노출** — 모델명(Claude/Sonar/OpenAI)·토큰·콜수는 3차로 격리. 사용자에겐 "참모"·"검색 근거" 같은 일상어만.
- **P3 큰 글씨·낮은 밀도** — 기본 화면의 1차 액션 ≤ 3개.
- **비용 예외** — 비용 *상세*는 3차로 숨기되, **한도 임박 경고(80% 경고·100% 일시정지)만 1차로 승격**한다(§8).

## 1. 정보구조 3영역

```
┌──────────────┬───────────────────────────────────────────┐
│ A. 대화 목록   │ 상단바: 앱명 · 참모진 상태칩(통합) · 비용(은은)   │
│ (사이드바)     ├───────────────────────────────────────────┤
│              │ B. 대화 메타 헤더(제목·태그·턴수·집계상태)        │
│  + 새 대화    │ ★ 이 질문의 핵심 쟁점 1줄 (1차 · 항상 노출)      │
│  + 검색      │ C. 가로 6단계 진행 스텝퍼 (현재 턴 기준)          │
│  종목 태그필터 ├───────────────────────────────────────────┤
│  핀 고정      │ D. 스레드 본문                                │
│  오늘/어제/…  │   - 이전 턴들: 접힌 카드(질문+알맹이+상태)         │
│  대화1 ····· │   - 현재 턴: 활성 단계 패널(①~⑥)               │
│  대화2 ····· │   - 하단: 후속 입력창 + '이전 대화 이어서 묻기'     │
│              │ 면책 배너(상시): "추천 아님 · 판단 기준점"         │
└──────────────┴───────────────────────────────────────────┘
```
- 6단계 인디케이터는 (목업의) 좌측 스텝퍼에서 **콘텐츠 상단 가로 스텝퍼**로 이동 — 좌측은 대화 목록이 차지.
- **★ 이 질문의 핵심 쟁점 1줄**은 1차 요소(§0)로 대화 헤더 아래·스텝퍼 위에 상시 노출. 생성은 §6 ①.
- 상단바 연결 표시는 **통합 "참모진 상태" 칩 1개**, 비용은 **은은한 표시**(상세는 3차) — §8.
- 사이드바는 **아이콘 모드로 접기** 가능.

## 2. A. 대화 목록(사이드바) — 정보 요소

- **항목당**: 제목(첫 질문 자동요약, 편집가능) · 상대시간("2시간 전") · 상태 배지(진행중/완료/일시정지/오류) · 미리보기 1줄(최신 알맹이, 없으면 최신 질문)
- **구조**: 핀 고정 섹션 → 시간 그룹(오늘/어제/지난 7일/이전), 최신 갱신순
- **종목 회고 동선**: 목록 상단에 **종목/테마 태그 필터 칩** 행. 칩 선택 시 해당 종목 대화만 추려 보기(시간 그룹 유지) — 사장님의 "삼성전기 관련 내가 뭐랬지" 회고 지원.
- **컨트롤**: "새 대화" 버튼 · 검색(제목+질문+알맹이+**태그** 텍스트)
- **항목 액션**(⋯): 이름변경 · 핀 · 태그(종목/테마) · 삭제 · 대화 전체 내보내기(PDF)

## 3. 멀티세션 모델 (대화 = 스레드, 턴 = 질문)

- **대화(conversation)** = 사이드바 1항목 = 여러 **턴**의 정렬된 모음
- **턴(turn)** = 질문 1건이 6단계 파이프라인을 1회 통과한 단위
- **흐름**
  - 생성: 새 대화 → 첫 질문 → 6단계 실행 → 턴1 → 제목 자동(편집가능)
  - 이어가기: 활성 대화 하단 입력창에 후속 질문 → 턴2 추가(6단계 재실행), 스레드에 누적
  - **이전 대화 이어서 묻기**(토글, 같은 대화 후속 턴 **기본 ON**): 지난 턴의 **근거·알맹이를 그대로 이어** 물어 불필요한 검색 재호출을 줄임(사장님 반복 질문식). 사용자 문구 = "지난 근거·결론을 그대로 이어서 물어봅니다(다시 검색 안 함)."
    - **stale 방지(필수)**: 재사용 시 **"근거 수집: N일 전" 표시 + "근거 새로고침" 1탭**을 함께 노출. 시간 민감한 종목에서 오래된 근거로 오판하지 않도록(설계원칙: 근거 우선). 비용 기본값(Sonar 재호출 절감)은 보존하되 신선도는 사용자가 즉시 통제.
  - 재방문: 사이드바에서 과거 대화 선택 → 스레드 복원, 임의 턴 펼쳐보기 또는 "이 지점에서 이어가기"

## 4. D. 스레드 본문 표시

- **이전 턴**: 접힌 카드 = 질문 + 알맹이 1줄 + 상태배지. 펼치면 그 턴의 6단계 상세
- **현재 턴**: 최상단에 **이 질문의 핵심 쟁점 1줄**(1차) → 상단 가로 스텝퍼로 ①~⑥ 이동(완료 단계 점프 가능, 미완 단계 비활성) → 활성 단계 패널 표시
- **후속 입력창**: 항상 스레드 맨 아래(채팅 앱 관성)

## 5. 상태 표현 (사이드바 항목 + 턴 헤더 양쪽)

| 상태 | 표시 정보 |
|---|---|
| 진행중 | 현재 단계명("참모 토론 중…") + 진행 인디케이터 |
| 완료 | 완료 배지 + 알맹이 요약 |
| 일시정지(한도) | 사유("월 크레딧 도달") + N분 후 재개 + 재개 버튼 |
| 오류 | 실패 단계 + 재시도 버튼 + (정족수 미달 시) 안내 |

- 대화 집계 상태 = 최신 턴의 상태
- ※ 이 표는 **턴/대화의 작업 상태**(파이프라인 진행). **참모진 연결 상태**(준비됨/점검 중)는 별개이며 §8.

## 6. 단계별 정보 요소 (현재 턴 콘텐츠)

- **① 질문**: **붙여넣기 영역**(다글로로 받아쓴 텍스트를 붙여넣는 큰 입력창 + 안내문 — v1은 붙여넣기, 라이브 STT 아님: FR-1/N5) · 원문 · 정제 질문 · 선택된 근거 축 목록 · **"이 질문의 핵심 쟁점 1줄"** · **"좋은 질문 먼저(질문 정제)" 토글**
  - **핵심 쟁점 1줄은 "좋은 질문 먼저" 토글과 분리한다.** 토글은 질문 *정제*만 켜고 끈다. 쟁점 1줄은 **토글 상태와 무관하게 항상 경량(1콜) 생성** — 결론이 아니라 *무엇이 걸려 있나*라는 **프레임**(예: "이 질문의 핵심 = 동조화 60%를 정점으로 볼 거냐"). 생성 실패/미가용 시 **fallback = 원문 질문**을 쟁점 자리에 노출(빈칸 금지).
- **② 근거**: 근거 카드(근거ID `Ek` · 축 · 텍스트 · 출처 · `단일출처` 배지) · 출처 클릭 이동. 기본은 핵심 근거 우선, 나머지는 "더 보기"(2차 밀도).
- **③ 참모진 토론**: → **§7 토론 전사 뷰** (이 단계가 핵심, 별도 상술)
- **④ 왜**: 노드(레벨 · 질문 · 답 · `근거기반/추론` 배지) · "왜? 더 파기" · 직접 주입 입력 · 충돌 플래그
- **⑤ 알맹이**: 합의 / 미합의 / 신뢰도 / kernel(기준점)
- **⑥ 보고서**: 전문가↔어린이 토글 · PDF 내보내기 · (영상 = "향후 외부도구")

## 7. ③ 참모진 토론 — 전사(Transcript) 뷰  ★핵심

목적: 참모들이 **돌아가며 발언하고 서로 받아치는 모습**을 사장님이 직관적으로 보게 한다. 카드 나열(의견 게시판)이 아니라 **그룹챗식 순차 전사**로 표현.

### 7.1 표현 방식
- **전사 상단 고정 안내(사용자 문구 · 정직성)**: "참모진은 **기본 2단계**로 토론합니다 — ① 각자 의견 → ② 서로 반박. 더 깊게 보려면 '한 라운드 더'." → 토론 구조를 **평문으로 정직하게** 드러냄('연출' 같은 단어는 사용자에게 쓰지 않는다).
  - **'한 라운드 더'로 라운드가 늘면 이 문구도 현재 라운드 수를 반영**("기본 2단계 + 추가 N회").
- 발언이 **정해진 순서로 하나씩 등장(스트리밍)** → "돌아가면서 발언" 직관 구현
- **발언 순서**(예): R1 `가치→모멘텀→반론→사실검증` → R2 `반론→사실검증→가치→모멘텀` → 종합 참모 마무리
- **"지금 발언 중" 인디케이터**(스트리밍 중 누가 말하는지)

### 7.2 발언 말풍선 — 정보 요소
- 참모 이름 · 역할 아이콘
- 라운드 라벨: `1차 의견` · `2차 반박` · `종합` (이 라벨이 정직성의 1차 운반체)
- 발언 본문
- 인용 근거칩: `E3` + 상태(`검증됨` / `의견(미검증)`)
- 신뢰도: 상 / 중 / 하

### 7.3 반박의 시각화 (토론이 보이게 하는 장치)
- R2 발언은 **대상 발언을 인용해 연결**: 예) `➥ 가치 참모의 "동조화 60% = 정점 임박"에 반박`
- **충돌 지점 하이라이트**: 두 참모가 같은 근거(`E#`)를 두고 갈리면 두 말풍선을 시각적으로 묶고 상단/우측에 "충돌 요약" 표시

### 7.4 토론 깊이 — 하이브리드 (사장님 결정)
- 기본: **2라운드(R1 독립 의견 → R2 상호 반박) + 종합**을 순차 전사로 표현 (백엔드 비용 통제 구조 그대로)
- **"한 라운드 더" on-demand 버튼**: 라벨은 **행동만**("참모 토론 한 번 더 ▸"). 누르면 R3 반박 라운드 1회 추가 생성(반복 가능). 깊이를 사장님이 직접 통제(인지적 마찰 보존).
  - **과금 경고를 마찰 장치에서 분리**: 버튼에 비용 문구를 붙이지 않는다. 추가 호출은 텔레메트리에 조용히 반영하고, "추가 토론 N회" 작은 카운터로만 표시. **한도 임박 시에만** 버튼 비활성 + 안내(§8).
- 정직성: 사용자 가시 정직성은 §7.1 상단 안내가 담당. (내부 구현 주석은 문서/코드 주석에만 두고 사용자에겐 노출하지 않는다.)

## 8. 비용 · 연결 정보 요소

### 8.1 연결 — 통합 "참모진 상태" 칩 (기술명 비노출)
상단바의 연결칩 3개를 **단일 "참모진 상태" 칩**으로 통합. 3-state + 정족수(참모≥2 + 사실검증1, FR-11) 매핑:

| 상태 | 의미 | 예 |
|---|---|---|
| `준비됨 ●` | 모든 경로 정상 | — |
| `일부 점검 중 ▲` | 일부 경로 장애지만 **정족수 충족 가능 → 진행** | 반론(OpenAI)만 장애 → 가치·모멘텀·사실검증 유지(반론 누락 표시) |
| `점검 중 ✕` | **정족수 불가 → 질문 차단** | **사실검증(Sonar) 장애 = 근거 0건 → 토론 차단(FR-11)**, 또는 종합(Opus) 장애 |

- 칩 클릭 → 경로별 상세 팝오버(Claude / Sonar / OpenAI 개별 상태) — **3차, 기본 숨김**.

### 8.2 비용 — 평시 은은 / 상세 3차 / 임박만 1차
- **전역 상단바**: 숫자 게이지 상시 노출 폐지 → 평시 **은은한 1점 표시**. **한도 임박만 1차 예외 승격**(80% 경고색 · 100% 일시정지 안내).
- **비용 상세(3차, 요청 시)**: "비용 보기" 클릭 → 별도 패널에 이번 달 사용량 · 턴/대화별 호출수 · 토큰 · 추가 라운드 사용 횟수 · 일시정지 사유. 투명성(NFR-3)은 보존하되 평시 흐름에서 비가시.

### 9.1 최초 실행 온보딩 (3스텝 · 선형 · 3-pane 밖 · 큰 글씨)
1. **Claude 로그인** — "Claude 로그인" 버튼 → setup-token OAuth. 실패 시 **API 키 입력 폴백**(PRD §4.5).
2. **검색·반론 참모 키 입력** — Perplexity Sonar · OpenAI 키 1회 입력(safeStorage 저장, 외부 전송 없음).
3. **준비 완료** → 첫 질문 화면으로.

- 원칙: **1스텝 1행동**, 큰 버튼·큰 글씨(NFR-7).

### 9.2 빈 상태 / 첫 질문 가이드
- 대화 없음 → 빈 상태 + "새 대화" + **"이렇게 물어보세요" 예시 질문 4개**(탭하면 질문칸에 **질문 텍스트만 프리필** — 가공된 근거·토론·알맹이는 **보여주지 않는다**).
- 예시 질문(사장님 녹취록 사례 기반):
  1. "우주항공(스페이스X 테마) 주가가 계속 오르는데 — 지금 들어가도 될까?"
  2. "네이버는 사상 최대 실적인데 왜 안 오르고, 삼성전기는 왜 오르나?"
  3. "한 제약주가 128만원까지 갔다가 34만원이 됐는데 — 이런 붕괴는 왜 생기나?"
  4. "비트코인을 2만개 샀다가 불안해서 3일 만에 팔았는데 — 언제까지 들고 있어야 하나?"
- **다글로 붙여넣기 안내**: "음성으로 받아쓴 텍스트를 그대로 붙여넣어도 됩니다"(§6 ①).

## 10. SQLite 스키마 매핑 (PRD §4.7 확장)

```
conversations(id, title, tag, pinned, status, created_at, updated_at)   -- 신설(사이드바)
turns(id, conversation_id FK, turn_index, question_raw, question_refined,
      crux, axes_json, inherit_context BOOL, status, created_at)        -- 기존 sessions = turn
evidence / council / why_nodes / synthesis / reports : turn_id로 기존 유지
council.round : 1, 2, 3.. (on-demand 추가 라운드 수용)
telemetry : turn 비용 → conversation 비용 롤업 (+ 추가 라운드 카운트)
```
- 사이드바 = `conversations` 조회. **종목 태그 필터 = `conversations.tag`** 재사용.
- 본문 = `turns WHERE conversation_id=? ORDER BY turn_index`
- **`turns.crux`** = 이 질문의 핵심 쟁점 1줄(§6 ①, 항상 생성, fallback=원문 질문).
- `conversations.status / updated_at` = 최신 turn에서 파생
- 전사 뷰 = `council WHERE turn_id=? ORDER BY round, speak_order`
- **연결 상태(§8.1)·비용 표시 위계(§8.2)는 런타임/표시 결정** — 스키마 변경 없음.

## 11. 결정 로그

1. **대화 단위** → 여러 질문 턴을 담는 스레드. Claude/GPT식 이어가기 + 사장님 반복 질문 습관.
2. **6단계 인디케이터 위치** → 콘텐츠 상단 가로 스텝퍼. 좌측은 대화 목록 차지.
3. **사이드바 항목 정보** → 제목·상대시간·상태배지·미리보기 1줄.
4. **목록 정렬/그룹** → 핀 + 시간 그룹.
5. **검색 범위** → 제목+질문+알맹이(+태그).
6. **항목 액션** → 이름변경/핀/태그/삭제/대화 PDF 내보내기.
7. **사이드바 접기** → 아이콘 모드.
8. **대화 생성** → 새 대화→첫 질문→턴1, 제목 자동(편집).
9. **이어가기** → 하단 입력창→새 턴, 6단계 재실행.
10. **이전 대화 이어서 묻기** → 토글로 근거·알맹이 재사용, 후속 턴 기본 ON + 근거 수집 시각·새로고침.
11. **이전 턴 표시** → 접힌 카드(질문+알맹이+상태), 펼침/이어가기.
12. **턴-파이프라인 관계** → 1 턴 = 6단계 1회, 스텝퍼는 턴 단위.
13. **상태 표현** → 진행중/완료/일시정지/오류, 사이드바+헤더.
14. **대화 메타 헤더** → 제목·태그·턴수·집계상태.
15. **단계별 정보 요소** → §6 ①~⑥ 명세.
16. **비용·연결 정보** → 전역 표시 + 턴/대화별(§8).
17. **빈/최초 상태** → 온보딩 3스텝 + 첫 질문 가이드(§9).
18. **스키마 매핑** → `conversations` 신설 + `sessions`→`turns`(+`crux`).
19. **③ 토론 표현** → 카드 나열 → **그룹챗식 순차 전사 뷰**(돌아가며 발언). 사장님 직관 요구.
20. **반박 시각화** → R2가 대상 발언을 인용 연결 + 충돌 지점 하이라이트. "토론"이 보이게.
21. **토론 깊이** → **하이브리드**: 2라운드 기본 + "한 라운드 더" on-demand. 비용 통제 + 사장님 깊이 통제(사장님 결정).

> **v1.1 개정** — 사용자(사장님) 관점 평가 → grill-yourself(개정 7) → grill-review(auto) 반영.

22. **표시 위계** → §0 표시 원칙 신설(1차/2차/3차 + 기본 단순 · 기술 용어 비노출). 55세 비기술(NFR-7).
23. **턴 핵심 쟁점 1줄** → 1차 상시 노출. **질문 정제 토글과 분리해 항상 생성**(결론 아닌 프레임), fallback=원문 질문. `[grill-review Blocker 반영]`
24. **연결 상태** → 칩 3개 → 통합 "참모진 상태" 1개(준비됨/일부 점검중/점검중), 정족수 매핑. **Sonar 장애=근거 0건→차단(red)**. `[Advisory 반영]`
25. **비용 표시** → 평시 은은 + 상세 3차(요청 시), 한도 임박만 1차 승격. "한 라운드 더"는 행동 라벨만(과금 경고 분리). `[Advisory 반영]`
26. **정직성 가시화** → 전사 상단 고정 1줄로 2단계 구조 평문 노출(현재 라운드 수 반영), '연출' 단어 비사용. `[Advisory 반영]`
27. **토글·검색 사용자 언어** → "이전 대화 이어서 묻기"(후속 기본 ON) + 근거 수집 시각·새로고침. 사이드바 종목/태그 필터 회고 동선. `[Advisory 반영]`
28. **온보딩·첫 질문** → §9 확장: 최초 실행 3스텝 + 예시 질문 4개(질문만 프리필). `[Advisory 반영]`
