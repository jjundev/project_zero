## 1. 배경 (Background)

사장님은 주식·투자 판단을 위해 이미 **다중 AI를 수동으로 활용**하는 독자적 워크플로우를 갖고 있다 (출처: `STT/0529` 미팅 녹취록).

- Perplexity로 검색 근거 수집 → Claude로 추론 → 답을 복사해 다른 AI에 붙여 **교차 검증·반박**
- "참모"를 만들어 **토론·의결**시키기
- "왜?"를 **5~7단계** 파고들기
- 학습 후 의견 받기, 어린이도 알 수 있게 정제, PDF·보고서 산출

이 과정은 전부 **수동 복붙**이라 마찰이 크고 느리며 누락이 잦다. 본 도구는 이 워크플로우의 **기계적 마찰만 제거**하고, 사고를 깊게 만드는 **인지적 마찰(왜 파기·참모 충돌)은 보존**하여 증폭한다.

> 핵심 철학: 자동화가 아니라 **"사장님의 사고 워크플로우를 시각화·증폭하는 도구"**. 사장님이 직접 경계한 "최면(에코챔버)"에 빠지지 않도록 반-편향 장치를 코드에 내장한다.

## 2. 목표 / 비목표

### 2.1 목표 (Goals)
- G1. 사장님의 6단계 워크플로우를 하나의 GUI 파이프라인으로 구현한다.
- G2. **검색 근거 우선** 원칙을 추론 단계까지 강제하여 환각을 차단한다.
- G3. 성향이 다른 **참모진이 서로의 주장을 실제로 반박**하는 토론으로 알맹이(기준점)를 도출한다.
- G4. 비용을 **예측 가능**하게 유지한다(구독 정액 + 소액 종량, 종량 폭탄 없음).
- G5. 모든 과정·산출물이 **사장님 본인 기기/계정** 안에서 동작한다(ToS·프라이버시).

### 2.2 비목표 (Non-Goals)
- N1. 종목 추천·매매 실행·증권사 연동 (자문 전용, §9).
- N2. 멀티유저·SaaS·외부 판매 (v1은 사장님 1인 전용).
- N3. 영상/만화 생성 (현 스택 불가, §8·§10).
- N4. 사주 기반 개인화 (후속 모듈, §10).
- N5. 라이브 음성인식(STT) 직접 통합 (v1은 다글로 텍스트 붙여넣기).

## 3. 설계 원칙 (Design Principles)

1. **근거 우선** — 참모는 자기 생각 전에 검색 근거(Sonar)를 먼저 깐다. 모든 주장은 근거ID를 인용하고, 인용은 **결정적 대조 + closed-book 함의 검증**으로 확인된다.
2. **마찰의 재배치** — 복붙 같은 기계적 마찰은 제거, "왜 파기"·참모 충돌 같은 인지적 마찰은 사장님이 직접 통제하도록 보존.
3. **반-에코챔버** — 사장님 프레임을 일부 참모엔 주입하되, **반론 참모는 별도 모델 패밀리 + 프레임 미주입 + 반증 의무**로 둔다. 참모는 **서로의 의견을 읽고 반박**한다(단순 병렬 독백 금지).
4. **정직한 합의** — 결론을 억지로 하나로 만들지 않고, 합의/미합의/신뢰도를 분리 제시. 산출은 정답이 아니라 **흔들리지 않는 기준점**.
5. **사장님 소유** — 실행·자격증명·데이터가 전부 사장님 통제 하에. 개발자는 빌드·설치·업데이트만.

## 4. 시스템 아키텍처

### 4.1 기술 스택 (확정)

| 구성요소 | 선택 | 인증/과금 | 비고 |
|---|---|---|---|
| 런타임·패키징 | **Electron + TypeScript** | — | GUI+오케스트레이터 단일 설치본, 더블클릭 실행 |
| 오케스트레이터 | **Claude Agent SDK** (subagents) | 사장님 Claude **Max OAuth** (기본) / **API 키 폴백** | 검증된 Scenario A. OAuth 미동작 시 API-키로 폴백 |
| 검색 근거 수집 | **Perplexity Sonar API** (`sonar`) | 사장님 Sonar 키 (소액 종량) | OpenAI 호환 API |
| 반론 참모(Red Team) | **OpenAI API** (모델 ID 고정) | 사장님 OpenAI 키 (소액 종량) | 2번째 모델 패밀리 = 진짜 독립성 |
| 종합/판결 | **Claude Opus** | Max OAuth/폴백 | 비싼 호출 최소화 |
| 페르소나·요약·왜·질문설계·어린이·**인용 함의 검증** | **Claude Sonnet** | Max OAuth/폴백 | 모델 티어링 |
| 시크릿 저장 | **Electron `safeStorage`** | 사장님 기기 | keytar(중단됨) 대신 내장 암호화 사용 |
| 세션 저장소 | **로컬 SQLite** | 사장님 기기 | 일시정지·재개·참모 재활용 |
| 실행 형태 | **사장님 PC 로컬 데스크톱 앱** | — | 개발자 호스팅 금지(ToS), 빌드·설치만 |

> **참모 인터페이스는 provider-agnostic**(`Participant.respond()`). v1은 위 조합, 추후 모델 패밀리 추가·교체 가능. 인스톨러는 Agent SDK가 의존하는 **Claude Code 엔진/바이너리를 동봉·설치**한다.

### 4.2 데이터 흐름 (한 턴 = 질문 1건 기준)

```
사장님 질문(음성→다글로 텍스트 붙여넣기)
   │
[질문 설계 참모] (토글, 기본 ON) 질문 정제 + 이 질문에 필요한 근거 축 선택
   │
[STEP2] Sonar 근거 쿼리(선택된 축, 병렬) → 근거 카드(출처·근거ID E1..En 부여)
   │
[STEP3] 참모진 2라운드 토론 (근거ID 인용 강제)
   ├─ R1 독립 의견(병렬): 가치 / 모멘텀 / 반론 / 사실검증
   └─ R2 상호 반박: 각 참모가 타 참모 R1 의견을 읽고 반박(특히 반론 참모)
   │
[인용 검증기] (1)근거ID 실재 대조(결정적) → (2)Sonnet closed-book 함의 판정
   │            └─ 미검증 인용 차단 / ' 의견(미검증)' 강등
[STEP4] 왜? 5~7단계 (자동 3단계 후 on-demand, 사장님 직접 ‘왜?’ 주입, 근거기반/추론 배지)
   │
[STEP5] 종합/판결 (Opus) → 합의 / 미합의 / 신뢰도(상·중·하) → 알맹이(기준점)
   │
[STEP6] 1페이지 보고서 → 어린이 버전(1패스+1자기비평) 토글 → PDF 내보내기
   │
세션 레코드 영속화(SQLite) — 재열람·재개·참모 재활용
```

### 4.3 참모 구성 (반-편향)

| 참모 | 모델 | 역할 | 편향 방어 |
|---|---|---|---|
| 가치 참모 | Claude/Sonnet | 보수·본질·정점 경계 | 프레임 주입 |
| 모멘텀 참모 | Claude/Sonnet | 공격·추세·서사 | 프레임 주입 |
| **반론 참모** | **OpenAI(고정 모델)** | 프레임 자체 공격·반증 | **다른 패밀리 + 프레임 미주입** |
| 사실검증 참모 | Perplexity Sonar | **근거 제공·사실 확인** (함의 판정은 Sonnet) | 다른 패밀리 = 다양성 앵커 |
| 종합/판결 | Claude/Opus | 충돌 정리·기준점 도출 | 미합의·신뢰도 명시 의무 |

### 4.4 오케스트레이션 메커니즘
- **2라운드 단발 구조**(무한 토론 루프 금지): R1 독립 병렬 → R2 상호 반박 1회 → 종합 1회. 사장님 핵심인 "충돌·반박"을 실제 구현하되 비용을 통제.
- 참모 출력은 **구조화 JSON 스키마** 강제:
  ```
  Opinion { advisor, round, stance:string,
            claims:[{ text, cites:["E2","E4"], status?:"검증됨|의견" }],
            rebuts?:[{ target:advisor, point:string }],   // R2 전용
            confidence:"상|중|하" }
  ```
- `Participant` 인터페이스: `respond(ctx): Promise<Opinion>`. 구현체 `ClaudeParticipant`(Agent SDK)·`SonarParticipant`·`OpenAIParticipant`. council은 `council.config.ts`에서 조립.

### 4.5 인증 · 시크릿 · 온보딩
- **Claude Max**: 앱 내 "Claude 로그인" 버튼이 `setup-token` OAuth 플로우 구동 → 토큰을 `safeStorage`에 저장. **착수 시 'OAuth 토큰이 커스텀 앱 Agent SDK에서 동작'을 실측 검증**하고, 미동작 시 **API-키 입력 폴백**으로 자동 전환(앱은 두 경로 모두 지원).
- **Sonar·OpenAI 키**: 최초 실행 설정 화면에서 1회 입력 → `safeStorage` 저장. 외부 전송 없음.

### 4.6 프레임 아티팩트 (`src/config/framework.md`)
- 버전 헤더 + 섹션: `3축(금리/수급/서사)` · `매크로놈 동조화(0→100%·정점경계)` · `뉴스 빈도 추세` · `미래가치의 현재 대입` · `주기(10년/1년)` · `경계 신호(정점/붕괴/감정매도)`.
- 런타임 평문 로드 → **가치·모멘텀·종합 참모에만 주입**, 반론 참모엔 미주입.

### 4.7 멀티세션 · 세션 스키마 (SQLite)
대화(conversation) = 여러 질문 턴(turn)의 스레드. 사이드바·이어가기·토론 전사 등 GUI 정보구조는 `gui.md` 참조.
```
conversations(id, title, tag, pinned, status, created_at, updated_at)         -- 사이드바(스레드)
turns(id, conversation_id FK, turn_index, question_raw, question_refined,
      axes_json, inherit_context BOOL, status, created_at)                    -- 질문 1건 = 6단계 1회
evidence(id, turn_id, eid, axis, text, sources_json, source_count)
council(id, turn_id, advisor, model, round, speak_order, stance, claims_json, rebuts_json, confidence)
why_nodes(id, turn_id, level, question, answer, basis, evidence_refs)
synthesis(turn_id PK, consensus_json, dissent_json, confidence, kernel)
reports(turn_id, mode, html, pdf_path)
telemetry(id, turn_id, stage, model, in_tokens, out_tokens, calls)
```
- `conversations.status/updated_at`는 최신 turn에서 파생. `council.round`는 on-demand 추가 라운드(R3+) 수용, `speak_order`는 전사 뷰 발언 순서.

## 5. 워크플로우 6단계 명세

| 단계 | 입력 | 처리 | 출력 |
|---|---|---|---|
| ① 질문 | 사장님 텍스트(다글로 붙여넣기) | (옵션) 질문설계 참모가 질문 정제 + 필요한 근거 축 선택 | 정제 질문 + 축 목록 |
| ② 근거 수집 | 정제 질문 + 축 | Sonar 쿼리(선택 축, 병렬), dedup | 근거 카드 + 출처 + **근거ID** + 단일출처 플래그 |
| ③ 참모진 토론 | 질문 + 근거 | **R1 독립(병렬) → R2 상호 반박** → 인용 검증기 통과 | 참모별 입장·반박 + 충돌 지점 |
| ④ 왜? 5~7단계 | 토론 결과 | 자동 3단계 → on-demand 7, 사장님 직접 주입, 근거기반/추론 배지 | 인과 체인(≤7) |
| ⑤ 충돌→알맹이 | 토론 + 왜 체인 | Opus 종합: 합의/미합의/신뢰도 분리 | 알맹이(기준점) |
| ⑥ 보고서/산출 | 알맹이 | 1페이지 보고서 → 어린이 버전(1패스+1자기비평) 토글 → PDF | 화면 보고서 + PDF |

## 6. 기능 요구사항 (Functional Requirements)

- **FR-1 질문 입력** — 텍스트 입력(다글로 붙여넣기 전제). 라이브 STT 비목표.
- **FR-2 질문 설계 토글** — 기본 ON. 질문설계 참모(Sonnet)가 질문 정제 + **이 질문에 필요한 근거 축을 동적 선택**.
- **FR-3 근거 수집** — Sonar로 선택된 축 쿼리를 병렬 실행, dedup → 근거 카드. 각 근거에 **근거ID·출처·source_count** 부여.
- **FR-4 출처 신뢰도** — 핵심 수치 source_count<2면 `단일출처` 배지.
- **FR-5 참모진 토론(2라운드 + 전사 뷰)** — R1 독립 의견(병렬) → R2 각 참모가 타 참모 의견을 읽고 반박. 모든 주장은 근거ID 인용 필수. UI는 **그룹챗식 순차 전사 뷰**로 발언을 하나씩 표시(돌아가며 발언)하고, R2 반박은 대상 발언을 인용 연결 + 충돌 지점 하이라이트. **"한 라운드 더" on-demand 버튼**으로 사장님이 추가 반박 라운드(R3+)를 직접 요청(하이브리드 깊이). 정보구조 상세 `gui.md` §7.
- **FR-6 인용 검증기** — (1) 결정적: 인용 E#가 evidence에 실재하는지 대조, 없으면 제거+플래그. (2) **Sonnet closed-book 함의 판정**(제공 텍스트만 보고, 검색 재트리거 없음): 근거가 주장을 뒷받침하지 않으면 `의견(미검증)` 강등.
- **FR-7 왜? 심화** — 자동 3단계 생성 후 "왜? 더 파기"로 ≤7까지 on-demand. 사장님이 노드에 직접 ‘왜?’ 주입 가능. 노드별 `근거기반|추론` 배지, 충돌 시 플래그.
- **FR-8 종합/판결** — Opus가 합의/미합의/신뢰도(상·중·하) 분리 출력 + 알맹이(기준점). 단일 결론 강요 금지.
- **FR-9 보고서** — 1페이지 보고서 생성. **어린이 버전 토글**(1패스+1회 자기비평, Sonnet). **PDF 내보내기**는 Electron `webContents.printToPDF()`로 동일 HTML 렌더.
- **FR-10 멀티세션 영속화** — 대화(스레드) = 여러 질문 턴. 좌측 대화 목록에서 선택·이어가기·재방문. 후속 턴은 이전 근거·알맹이 재사용(토글). 일시정지·재개·참모 재활용. 정보구조는 `gui.md`.
- **FR-11 장애 폴백** — 모든 호출 1회 지수백오프 재시도. Sonar 무응답 시 부분 근거+배너, **근거 0건이면 토론 차단**. 참모 실패 시 누락 표시 후 진행하되 **정족수(참모 ≥2 + 사실검증 1)** 미달이면 종합 불가. 한도 초과 시 부분 세션 저장→pause→resume.
- **FR-12 비용 게이지** — 월 Claude 참모 크레딧 사용량 표시, 80% 경고 / 100% 일시정지.
- **FR-13 진행 스트리밍 UI** — 파이프라인은 수초~수분 소요. 렌더러는 단계별 부분결과(근거→R1→R2→왜→종합)를 **스트리밍 표시**하며 로딩·에러 상태를 처리한다.
- **FR-14 텔레메트리** — 단계별 호출수·토큰을 `telemetry` 테이블에 기록해 비용 캡 실측 보정.

## 7. 비기능 요구사항 (Non-Functional Requirements)

- **NFR-1 Fan-out 상한** — 질문당 기본: Sonar(선택 축, ≤5) + 참모 R1 4 + R2 4 + 종합 1 + 자동 왜 3 ≈ **17 calls**, 이후 왜는 on-demand. 페르소나·요약·왜·질문설계·어린이·함의검증=Sonnet, 종합=Opus. 질문+근거 공통 프리픽스 **프롬프트 캐싱**. **추가 토론 라운드(R3+)는 사장님 on-demand 시에만 +4 calls/라운드**로 캡·텔레메트리에 반영(한도 임박 시 버튼 비활성).
- **NFR-2 토큰 캡** — 질문당 소프트 100k / 하드 150k(초과 시 중단·안내). 캡은 텔레메트리(FR-14)로 보정하는 **잠정 기본값**.
- **NFR-3 예측 가능 비용** — Claude Max 정액(agent credit $100/$200, 소진 후 API 요금) + Sonar ~$5–18/월 + OpenAI(반론 한정) 소액. 모두 사장님 본인 계정/키.
- **NFR-4 ToS 준수** — 사장님 본인 OAuth(또는 본인 API 키)로 본인 기기 구동(Scenario A). 개발자 호스팅·자격증명 라우팅 **금지**.
- **NFR-5 프라이버시** — 세션·시크릿은 사장님 기기 로컬에만(`safeStorage`/SQLite). 외부 전송 없음.
- **NFR-6 신뢰성** — 단건 장애가 전체 파이프라인을 중단시키지 않음(FR-11).
- **NFR-7 사용성** — 비기술 55세 사용자 대상. 큰 글씨·명료한 한글 UI·단계형 진행(목업 기준).

## 9. 규제 / 법무

- 본 도구는 **자문 전용**이며 종목 추천·매매 실행·자금 이동을 수행하지 않는다.
- 모든 화면·보고서에 "종목 추천이 아닌 판단 기준점, 선택·책임은 사용자 몫" 상시 면책 표기.
- **단일 사용자(사장님 본인)** 자기 자문 용도이므로 자문업 규제 위험이 낮음.
- **제품화 게이트**: 타인 공유·판매·멀티유저 전환 시점에 자문업 인허가·ToS·라이선스를 **재평가**(이때 구독-한도 전략은 API 키 기반으로 전환 필요).

## 12. 결정 로그 — 핵심 설계

> grill-yourself(1차) 16 + grill-review(1차) 보완. `[검토반영]`=적대적 검토에서 수정.

1. **다양성 앵커** → Sonar(다른 패밀리)+반론 참모.
2. **프레임 주입 범위** → 가치·모멘텀엔 주입, 반론 참모엔 미주입+반증 의무.
3. **반론 참모 모델** → OpenAI(2번째 패밀리) `[검토반영]`.
4. **추론 환각 차단** → 근거ID 인용 강제 + 인용 검증기 신설 `[검토반영]`.

13. **운영/배포** → 사장님 본인 기기 로컬 구동(호스팅 금지) `[검토반영]`.

## 13. 결정 로그 — 구현 상세

> grill-yourself(2차) 20 + grill-review(2차) 보완. `[검토반영]` 표시분.

1. **런타임/패키징** → Electron + TypeScript.
2. **UI 자산** → 목업을 **데이터 주도 셸로 재작성**(스트리밍·상태) `[검토반영]`.
3. **Claude 인증** → setup-token OAuth + **API-키 폴백 + 착수 시 실측 검증** `[검토반영]`.
4. **시크릿 저장** → **Electron `safeStorage`**(keytar 중단) `[검토반영]`.
5. **Agent SDK 패키징** → 인스톨러가 Claude Code 엔진/바이너리 동봉 `[검토반영]`.
6. **참모 인터페이스** → provider-agnostic `Participant.respond()`.
7. **토론 방식** → **2라운드(독립→상호 반박) + 종합** `[검토반영]`.
8. **참모 출력** → 구조화 JSON(claims+cites+rebuts).
9. **근거 쿼리** → 질문설계 참모가 **필요 축을 동적 선택** `[검토반영]`.
10. **인용 검증** → ID 대조(결정적) + **Sonnet closed-book 함의**(Sonar 아님) `[검토반영]`.
11. **framework.md** → 버전 헤더 + 6섹션, 가치·모멘텀·종합에만 주입.
12. **질문 설계** → 토글(기본 ON), 질문설계 참모, 둘 다 표시.
13. **왜 체인** → 자동 3 + on-demand 7 + 사용자 주입.
14. **종합 출력** → consensus/dissent/confidence/kernel 스키마.
15. **어린이 버전** → 1패스 + 1회 자기비평(Sonnet).
16. **PDF** → Electron `printToPDF()`.
17. **세션 스키마** → SQLite 7테이블(telemetry 포함).
18. **비용 상한** → ~17 calls·토큰 소프트100k/하드150k·월 80/100% + **텔레메트리 보정** `[검토반영]`.
19. **반론 모델** → OpenAI **모델 ID 고정 + structured-output 확인** `[검토반영]`.
20. **장애 폴백** → 1회 백오프 + 정족수(참모≥2+사실검증) + pause/resume.

> **GUI 정보구조 동기화**: 멀티세션(대화=스레드/턴=질문), ③ 참모 토론의 그룹챗식 순차 전사 뷰, 하이브리드 토론 깊이("한 라운드 더" on-demand) 결정은 `gui.md` §11에 있고, 본 PRD의 §4.7(스키마)·FR-5·FR-10·NFR-1에 반영됨.
