# 제품 개요

> **버전:** v2.3 — 2026-05-28

---

## 1. 한 줄 정의

> **"투자 초보가 자신의 탐색 성향에 맞는 관점부터 시작해, 공개 지표로 기업을 좁혀 보고 알아보는 앱"**

본 제품의 첫 가치는 **살 기업을 골라주는 것**이 아니라, **기업을 볼 첫 질문을 만들어 주는 것**이다.

사용자는 탐색 관점을 고르고, 그 관점에 연결된 공개 지표·출처·기준일을 확인한 뒤, 한 번 더 볼 기업을 `다시 보기`로 남긴다. 단, 탐색 성향은 특정 기업이나 매매 판단에 연결하지 않는다. 성향은 사용자가 공개 지표를 어떤 관점에서 볼지 고르는 출발점으로만 사용한다.

Phase 1은 **성향 기반 종목 추천 앱**이 아니라 **성향 기반 탐색 입문 앱**이다. 이 차이를 제품 구조, 카피, 이벤트, 법무 검토 패키지에서 모두 유지한다.

---

## 2. 첫 사용자 상황

Phase 1의 첫 사용자는 **개별 기업 이름은 들어봤지만, 투자 판단 전에 어떤 공개 정보부터 확인해야 할지 모르는 사람**이다.

대표 상황은 다음과 같다.

- 이름은 들어본 기업이 있지만, 재무제표·공시·지표 중 무엇을 먼저 봐야 할지 모른다.
- 커뮤니티나 뉴스에서 기업명을 접했지만, 바로 판단하기보다 공개 지표를 확인해 보고 싶다.
- 증권 앱의 숫자와 공시 목록은 부담스럽고, 처음 던질 질문 하나가 필요하다.
- 기업을 사야 할지보다, 그 기업을 알아보기 위해 어디서부터 봐야 하는지가 더 막막하다.

---

## 3. 사용자가 얻는 변화

이 앱은 사용자를 다음 상태로 이동시키는 것을 목표로 한다.

| 전 | 후 |
|---|---|
| 기업명은 알지만 무엇을 봐야 할지 모른다 | 내가 고른 탐색 관점에 따라 확인할 공개 지표 하나를 이해한다 |
| 숫자와 공시가 모두 투자 판단처럼 느껴진다 | 공개 지표, 출처, 기준일을 분리해서 확인한다 |
| 바로 판단해야 할 것처럼 느낀다 | 당장 판단하지 않고 다시 볼 기업으로 남긴다 |
| 큰 종목 목록 앞에서 멈춘다 | 현재 켠 조건에 해당하는 적은 수의 기업부터 본다 |

성공한 첫 경험은 사용자가 특정 기업을 사야겠다고 느끼는 것이 아니다. **사용자가 그 기업을 보기 위한 첫 질문과 확인한 공개 지표를 자기 말로 설명할 수 있게 되는 것**이다.

## 4. 핵심 경험 한 장 요약

Phase 1의 제품 약속은 다음과 같다.

1. **탐색 성향 선택** — 사용자는 첫 진입에서 "어떤 방식으로 기업을 알아보고 싶은지"를 고른다.
2. **관점 설명** — 앱은 해당 성향에 연결된 공개 지표 관점을 설명한다.
3. **조건 직접 선택** — 사용자가 조건을 직접 선택하고 `이 조건으로 기업 보기`를 눌렀을 때만 결과를 보여준다.
4. **기업 좁혀 보기** — 결과는 사용자가 켠 조건에 해당하는 기업을 공개 지표와 함께 적은 수로 보여준다.
5. **사실 확인과 다시 보기** — 상세 화면에서 출처, 기준일, 조건 근거를 확인하고 다시 볼 기업을 `다시 보기`에 추가한다.

첫 사용 흐름은 기능 이동이 아니라 이해가 쌓이는 순서로 설계한다.

```text
탐색 관점 선택
  → 기업을 볼 때 던질 첫 질문을 고른다
조건 직접 선택
  → 앱이 대신 고른 조건이 아니라, 자신이 이해한 조건을 직접 켠다
결과 확인
  → 좋은 기업이 아니라 현재 켠 조건에 해당하는 기업을 적은 수로 본다
상세 확인
  → 조건이 어떤 공개 지표, 출처, 기준일에 근거하는지 확인한다
다시 보기 추가
  → 당장 투자 판단하지 않고, 한 번 더 확인할 기업을 남긴다
```

## 5. 핵심 재정의

### 5.1 왜 4th가 필요한가

3rd 문서는 법무 리스크를 줄이는 과정에서 "추천하지 않는다", "사주는 분리한다", "개인화하지 않는다"를 강하게 고정했다. 그 결과 안전성은 올라갔지만, 원래 만들고 싶었던 제품의 감각인 **"나 같은 사람은 무엇부터 보면 좋을까?"**가 약해졌다.

4th 문서는 다음 균형으로 재정의한다.

| 구분 | 3rd의 중심 | 4th의 중심 |
|---|---|---|
| 제품 정체성 | 조건 기반 기업 탐색 도구 | 탐색 성향 기반 기업 알아보기 도구 |
| 성향의 역할 | 사실상 제거 | 탐색 관점 선택에만 사용 |
| 추천 리스크 대응 | 성향/추천 표현을 회피 | 사람-종목 매칭 금지, 사람-관점 연결 허용 |
| 첫 화면 감각 | 조건을 직접 고름 | "어떤 방식으로 알아볼까?"에서 시작 |
| 결과 산출 | 사용자가 켠 조건 | 동일. 성향은 결과 산출에 직접 사용하지 않음 |

### 5.2 허용되는 성향과 금지되는 성향

허용되는 구조:

```text
사용자의 탐색 성향
→ 확인할 관점 설명
→ 사용자의 조건 직접 선택
→ 공개 지표 기반 결과
```

금지되는 구조:

```text
사용자의 투자 성향
→ 앱의 자동 조건 적용
→ 특정 종목 매칭
→ "당신에게 맞는 기업" 표현
```

성향은 다음 목적으로만 쓴다.

- 사용자가 첫 조건을 고르기 쉽게 돕는다.
- 조건의 의미를 입문자 언어로 설명한다.
- 기업을 볼 때 어떤 질문을 던지면 좋은지 알려준다.

성향은 다음 목적으로 쓰지 않는다.

- 특정 기업 추천
- 기업 정렬 가중치
- 사용자의 투자 적합성 판단
- 매수/매도/보유 판단
- 서버의 장기 관심 프로필 생성

## 6. 제품 철학

| 원칙 | 의미 |
|---|---|
| **성향은 종목이 아니라 관점에만 연결한다** | 사용자의 성향 입력은 "무엇부터 볼지"를 정하는 데만 쓰고, 특정 기업을 맞춤 추천하지 않는다. |
| **결과는 사용자가 직접 켠 조건으로만 나온다** | 탐색 성향을 골라도 결과는 바로 나오지 않는다. 사용자가 조건을 직접 선택하고 적용해야 한다. |
| **공개 지표를 먼저 본다** | 앱은 결론보다 공개 지표, 출처, 기준일, 조건 근거를 보여준다. |
| **적은 수로 좁힌다** | 초보자에게 큰 리스트를 던지지 않고, 조건에 해당하는 기업을 작은 묶음으로 보여준다. |
| **추천처럼 보이는 문장을 피한다** | "당신에게 맞는 기업", "추천 종목", "좋은 기업" 같은 표현을 쓰지 않는다. |
| **다시 보기는 투자 의향이 아니다** | 다시 보기는 머릿속 관심 기업을 잠시 외부화하는 기능이며, 매수 관심으로 해석하지 않는다. |
| **합법성을 UX 구조로 지킨다** | 디스클레이머만 붙이지 않고, 성향 선택, 조건 적용, 결과 문구, 정렬, 이벤트 저장 방식까지 법무 검토 대상으로 둔다. |

## 8. Phase 1 핵심 경험

### 8.1 탭 구조

Phase 1-B 외부 출시 시점은 2탭 구조다.

| 탭 | 책임 |
|---|---|
| **발견** | 탐색 성향 선택, 관점 설명, 조건 직접 선택, 조건 적용, 기업 결과 확인 |
| **관찰** | 다시 보기 목록, 새 공개자료 있음 인앱 점 표시, 상세 재진입 |

Phase 1-B에는 계정 가입, 서버 동기화, 사주 탭, 외부 알림, 수익률 입력, AI 투자 판단 문장, 자연어 조건 입력을 넣지 않는다.

### 8.2 첫 진입 흐름

```text
Splash
  → 발견 탭
  → "어떤 방식으로 기업을 알아보고 싶나요?"
  → 탐색 관점 1개 선택
  → 해당 관점의 공개 지표 설명 확인
  → 조건 1개 직접 선택
  → 이 조건으로 기업 보기
  → 현재 켠 조건에 해당하는 기업 확인
  → 기업 상세에서 공개 지표·출처·기준일 확인
  → 나중에 다시 보기
  → 관찰 탭에서 다시 확인
```

### 8.3 탐색 관점 카드

사용자 화면에서는 "투자 성향"보다 **"알아보는 방식"**, **"탐색 관점"**을 우선 사용한다. 내부 문서에서는 이를 `exploration_style`로 부른다.

| 탐색 관점 | 사용자 카피 | 함께 읽어볼 조건 | 설명 |
|---|---|---|---|
| **숫자로 차분히 보기** | "먼저 손익 흐름을 확인하고 싶어요" | 최근 영업이익 흑자 여부 | 최근 공개된 손익 지표를 먼저 본다. 미래 수익이나 주가 상승을 의미하지 않는다. |
| **변화 흐름부터 보기** | "최근 늘었는지 줄었는지 보고 싶어요" | 매출 또는 영업이익 증가 확인 | 최근 매출·영업이익의 증감 방향을 본다. 좋은 기업이라는 뜻은 아니다. |
| **최근 확인거리부터 보기** | "최근 새로 확인할 자료가 있는지 보고 싶어요" | 최근 확인할 주요 공개자료 | 최근 정기보고서나 주요사항보고서를 확인한다. 최신 공시가 긍정 신호라는 뜻은 아니다. |

탐색 관점 선택은 조건 자동 적용이 아니다. 관점을 선택하면 해당 조건 카드는 `함께 읽어볼 조건` 섹션에 설명과 함께 배치될 수 있지만, 체크 상태·강조 배지·추천 문구·결과 영역 자동 스크롤은 제공하지 않는다. 기업 결과는 사용자가 조건을 직접 선택하고 적용한 뒤에만 노출한다.

`설명부터 천천히 보기`는 탐색 관점 카드에서 제외한다. 대신 첫 방문 기본값으로 조건 카드의 `이 조건은 왜 보나요?` 설명을 펼쳐 보여주는 **학습형 표시**를 적용한다. 학습형 표시는 별도 토글이나 설정으로 만들지 않고, 결과는 동일하게 사용자가 조건을 직접 선택하고 적용한 뒤에만 노출한다.

### 8.4 조건 적용 정책

- 첫 조건 적용 전에는 조건 1개만 선택할 수 있다. 이는 조건의 의미를 한 개씩 학습하게 하기 위한 의도이며, 0개 결과 회피 목적이 아니다.
- 탐색 관점 선택 후에도 조건은 0개 상태로 시작한다.
- 사용자가 조건을 직접 선택하고 `이 조건으로 기업 보기`를 눌러야 결과가 나온다.
- 결과를 본 뒤 추가 조건을 켜거나 끌 수 있다.
- 조건 변경 후에는 다시 `이 조건으로 기업 보기`를 눌러야 결과가 갱신된다.
- 재방문 시 발견 탭의 조건과 탐색 관점은 초기화한다. 다시 보기 목록만 기기 로컬에 유지한다.

### 8.5 1-C-Saju 후보 실험: 사주 기반 탐색 기준 추천

사주는 Phase 1-B에 포함하지 않는다. 다만 Phase 1-B의 핵심 퍼널이 검증된 뒤, 확장 후보 실험 중 하나인 **1-C-Saju: 사주 기반 탐색 기준 추천**을 검토할 수 있다.

이 실험의 원칙은 다음 한 문장으로 고정한다.

> **사주는 종목을 추천하지 않고, 기업을 볼 때 던질 첫 질문을 정하는 데만 사용한다.**

허용되는 구조:

```text
사용자 사주
→ 오늘의 탐색 질문
→ 사용자의 조건 직접 선택
→ 공개 지표 기반 결과
```

금지되는 구조:

```text
사용자 사주
→ 사용자와 맞는 업종·기업·종목 산출
→ 사주 궁합 점수 또는 추천 결과
→ 투자 판단으로 해석되는 문장
```

사용자 화면의 기능명은 `사주 추천`, `사주 종목`, `재물운 종목`이 아니라 **`오늘의 탐색 질문`**을 우선 사용한다. 예시 카피는 다음과 같다.

> "사주로 종목을 고르지 않습니다. 오늘 기업을 볼 때 던질 첫 질문을 정합니다."

사주 입력 후에도 조건은 0개 상태로 시작한다. 사주는 조건을 자동 선택하거나 자동 적용하지 않으며, 결과 산출·정렬·다시 보기 구성에 영향을 주지 않는다. 사용자가 조건을 직접 선택하고 `이 조건으로 기업 보기`를 눌러야 결과가 표시된다.

1-C-Saju 후보 실험의 상세 설계는 [saju_exploration_question_design.md](saju_exploration_question_design.md)에 둔다.

### 8.6 1-C-NL 후보 실험: 문장으로 조건 찾기

자연어 조건 입력은 Phase 1-B에 포함하지 않는다. 다만 Phase 1-B의 핵심 퍼널이 검증된 뒤, 사용자가 조건을 고르기 어려워한다는 병목이 확인되면 확장 후보 실험 중 하나인 **1-C-NL: 문장으로 조건 찾기**를 검토할 수 있다.

이 실험의 원칙은 다음 한 문장으로 고정한다.

> **자연어 입력은 종목을 찾아주는 AI 검색이 아니라, 사용자의 문장을 기존 공개 지표 조건 후보로 바꾸는 입력 보조다.**

허용되는 구조:

```text
사용자 자연어 입력
→ 조건 후보 해석
→ 사용자의 직접 선택
→ 이 조건으로 기업 보기
→ 공개 지표 기반 결과
```

금지되는 구조:

```text
사용자 자연어 입력
→ AI가 종목 산출
→ 추천 이유 생성
→ 투자 판단으로 해석되는 문장
```

사용자 화면의 기능명은 `AI 종목 검색`, `AI 추천 검색`이 아니라 **`문장으로 조건 찾기`** 또는 **`찾고 싶은 기준 입력`**을 우선 사용한다. 입력 후에도 결과는 바로 노출하지 않는다. 앱은 조건 후보만 보여주고, 사용자가 조건을 직접 선택한 뒤 `이 조건으로 기업 보기`를 눌러야 결과가 표시된다.

종목명·종목코드·기업명으로 보이는 토큰이 입력에 포함되면 자연어 조건 변환을 중단한다. 금지 의도와 허용 조건이 섞인 문장도 전체 차단한다. 예를 들어 "안전하면서 매출 늘어난 회사"는 `안전`이 투자 적합성 판단을 요구하므로 조건 후보를 보여주지 않는다.

1-C-NL 후보 실험의 상세 설계는 [natural_language_condition_input_design.md](natural_language_condition_input_design.md)에 둔다.

### 8.7 재방문 사용자 경험

재방문은 첫 방문과 동일한 발견 탭 빈 상태에서 시작한다. 탐색 관점과 조건은 모두 초기화하며(§8.4 재확인), 카피와 금지 표현은 첫 방문과 동일하게 적용한다. 학습형 표시(§10.1)는 첫 방문에만 기본 펼침이고, 재방문에서는 기본 접힘으로 시작한다. 다시 보기 목록만 기기 로컬에 유지한다.

재방문 세션은 §14.1 North Star 산출에서 제외한다. 재방문 측정은 §13.2의 `watchlist_revisited` 이벤트로만 수행한다.

## 9. 조건 항목과 결과 산출

### 9.1 Phase 1-B 조건

Phase 1-B는 **3개 조건 + 1개 상태 정보**로 시작한다.

| 조건 | 의미 | 예시 근거 |
|---|---|---|
| **최근 영업이익 흑자 여부** | 최근 손익 관련 공개 지표 확인 | 최근 4분기 중 3분기 영업이익 흑자, 최근 보고서 기준 부채비율 |
| **매출 또는 영업이익 증가 확인** | 최근 매출 또는 영업이익의 증가 여부 확인 | 최근 분기 매출 전년 동기 대비 증가, 영업이익 전년 동기 대비 감소 |
| **최근 확인할 주요 공개자료** | 사용자가 먼저 확인할 만한 공개자료 존재 여부 | 최근 정기보고서 제출 또는 지정 주요사항보고서 |

| 상태 정보 | 의미 | 표시 |
|---|---|---|
| **최근 12개월 약한 주의 신호** | 유니버스 제외 기준보다 약한 주의 신호의 확인 결과 | `최근 12개월 확인된 신호 있음` / `최근 12개월 확인된 신호 없음` / `확인 지연` |

약한 주의 신호는 조건 토글이 아니다. 결과 카드와 상세 화면의 보조 상태로만 표시한다.

약한 주의 신호 카테고리는 유니버스 제외 사유(거래정지·관리종목·상장폐지 사유 발생)보다 약하지만 사용자가 한 번 더 확인할 만한 공시를 가리킨다. Phase 1-B 기준 본문 예시는 다음 3개로 시작한다.

- 불성실공시법인 지정
- 횡령·배임 혐의 발생
- 감사의견 비적정 (한정·부적정·의견거절)

전체 카테고리 enumeration과 critical 시장조치와의 매핑 기준은 별도 운영 부속서 `critical_data_gate_decision_table.md`에 둔다.

### 9.2 산출 방식

조건 항목은 **자동 룰 100%**로 운영한다. 운영팀은 특정 종목을 결과에 추가하거나, 숨기거나, 정렬을 올리거나, 문구를 수동으로 바꾸지 않는다.

| 조건 | 임시 산식 기본값 | 출처 | 갱신 주기 |
|---|---|---|---|
| 최근 영업이익 흑자 여부 | 최근 4개 분기 중 3분기 이상 영업이익 흑자. 부채비율은 표시 전용 참고 지표. | DART 분기·사업보고서 | 분기, 보고서 제출 T+1 |
| 매출 또는 영업이익 증가 확인 | 최근 분기 전년 동기 대비 매출 또는 영업이익 증가. 분기 부적합 시 최근 연간 전년 대비 fallback. | DART 분기·사업보고서 | 분기, 보고서 제출 T+1 |
| 최근 확인할 주요 공개자료 | 최근 90일 내 사업보고서·반기보고서·분기보고서 또는 지정 주요사항보고서 제출. | DART 공시 | 매일, 공시 게재 T+1 |
| 약한 주의 신호 | 최근 12개월 내 약한 주의 신호 카테고리 발생 여부. | DART 공시 | 매일, 공시 게재 T+1 |

조건별 데이터가 위 갱신 주기를 초과해 지연되면 기업 카드와 상세 화면에 `기준일 확인 지연` 보조 상태를 표시한다. 이 표시는 약한 주의 신호 상태 표시와 동일한 영역을 공유하며, 두 상태가 동시 발생하면 약한 주의 신호 상태를 우선 표시한다. 지연 임계와 알람 정책은 별도 운영 부속서 `operations_runbook.md`에 둔다.

Phase 1 유니버스는 **거래정지·관리종목·상장폐지 사유 발생 종목을 제외한 코스피·코스닥 전체**로 둔다. critical 시장조치 데이터 필수 세트가 확인되지 않으면 Phase 1-A 진입을 보류하거나, critical 제외 약속을 제거한 별도 제품 정의로 법무 재검토한다.

### 9.3 결과 노출 정책

| 결과 수 | 처리 |
|---|---|
| 0개 | "현재 켠 조건을 모두 만족하는 기업은 없습니다"와 고정 가이드 카피 `"조건을 줄여 다시 적용해 보세요"`만 표시. 어떤 조건을 끄라고 추천하지 않는다. |
| 1~3개 | 실제 개수만 표시 |
| 4개 이상 | 현재 정렬 기준에서 먼저 볼 기업 3개 + 더 보기 |

0개 결과에서 부분 매칭 기업은 제공하지 않는다. 사용자가 조건을 직접 줄이고 다시 적용해야 한다.

### 9.4 정렬 기준

디폴트 정렬은 추천 점수나 투자 매력도가 아니라 공개 가능한 기계적 기준으로 설명한다.

1. 종목별 가장 최근 갱신된 조건의 데이터 기준일 내림차순
2. 같은 기준일이면 시가총액 내림차순

사용자 화면 설명:

> "기준일이 최근인 공개 지표부터 보여드립니다. 기준일이 같으면 거래 규모가 큰 기업부터 정렬됩니다."

정렬 옵션은 Phase 1-B에서 다음으로 제한한다.

- 기준일 최신순
- 거래 규모가 큰 기업부터
- 최근 확인할 공개자료가 있는 기업부터

`나에게 맞는 순`, `추천순`, `투자 매력도순`, `성향 적합도순`은 금지한다.

## 10. 조건 학습 모듈

각 조건 카드에는 "이 조건은 왜 보나요?" 펼침 영역을 둔다. 탐색 관점에서 시작한 사용자가 조건을 이해하고 직접 선택하도록 돕는 장치다. 첫 방문에서는 이 설명을 기본 펼침으로 보여주는 학습형 표시를 적용하고, 재방문에서는 사용자가 이전에 닫은 상태를 기기 로컬에서 유지할 수 있다.

### 10.1 구조

- 조건 카드 하단에 배치한다.
- 첫 방문에서는 학습형 표시로 기본 펼침 상태를 사용한다.
- 재방문 또는 사용자가 한 번 닫은 뒤에는 기본 접힘 상태를 사용할 수 있다.
- 닫힌 상태는 동일 디바이스의 동일 앱 설치 세션 내에서만 유지한다. 재설치·디바이스 변경 시 다시 펼친 상태로 시작한다.
- 1조건당 2문장으로 제한한다.
- 1문장은 이 조건이 보는 공개 사실을 설명한다.
- 1문장은 이 조건이 의미하지 않는 것을 설명한다.
- 학습 카피는 법무 검토 패키지에 포함한다.

### 10.2 예시 카피

| 조건 | 학습 카피 |
|---|---|
| 최근 영업이익 흑자 여부 | "최근 영업이익 흑자 여부는 회사가 공개한 손익 지표를 확인합니다. 이는 미래 수익이나 주가 상승을 의미하지 않습니다." |
| 매출 또는 영업이익 증가 확인 | "매출 또는 영업이익 증가 확인은 최근 공개된 증감 방향을 살펴봅니다. 증가가 곧 좋은 기업이나 투자 적합성을 뜻하지 않습니다." |
| 최근 확인할 주요 공개자료 | "최근 확인할 주요 공개자료는 사용자가 먼저 읽어볼 공시가 있는지 보여줍니다. 최근 공시가 있다는 사실만으로 긍정 또는 부정 판단을 하지 않습니다." |

## 11. 기업 카드와 상세

### 11.1 기업 카드

기업 카드는 초보자가 한 번에 판단하지 않도록, 하나의 조건과 하나의 공개 지표를 연결해서 보여준다. 사용자는 카드에서 이 기업이 왜 현재 결과에 나왔는지, 어떤 공개 지표가 조건과 연결되는지, 그 지표의 기준일이 언제인지를 확인한다.

기업 카드는 다음 정보만 보여준다.

- 기업명
- 시장 구분
- 중립 요약: `이 기업은 현재 켠 조건 중 [조건명]에 해당합니다`
- 현재 켠 조건과 연결된 공개 지표 1개
- 데이터 기준일
- 약한 주의 신호 상태
- 상세 진입 CTA: `공개 지표 보기`

허용 표현:

- 현재 켠 조건에 해당하는 기업
- 조건과 연결된 공개 지표
- 공개 지표 보기
- 기준일 최신순

금지 표현:

- 당신에게 맞는 기업
- 추천 종목
- 지금 볼 종목
- 좋은 기업
- 안전한 기업
- 우수한 기업
- 검증된 기업
- 성향 적합 기업
- 사야 할 기업

### 11.2 기업 상세

상세 화면은 결론을 주는 곳이 아니라 근거를 확인하는 곳이다. 목적은 사용자가 결과 카드의 근거를 자기 말로 설명할 수 있게 되는 것이다.

포함:

- 기업명
- 현재 켠 조건 목록
- 조건별 공개 지표
- 출처
- 데이터 기준일
- 이 지표가 의미하지 않는 것
- DART 원문 링크
- 약한 주의 신호 상태
- critical 공시가 다시 보기 유니버스에서 확인된 경우 별도 표시
- 정보 오류 신고
- CTA: `나중에 다시 보기`

제외:

- 추천 이유 보기
- 매수/매도/보유 의견
- 목표가
- 예상 수익률
- AI 투자 판단 문장
- 공유하기
- 성향과 기업의 궁합/적합도

정보 오류 신고는 사용자 입력과 DART 원문 링크를 운영팀에 전달하는 경로다. 사용자 신고 내용과 DART 원문이 충돌하는 경우 DART 원문을 우선한다. SLA·운영 흐름·재공시 갱신 정책은 별도 운영 부속서 `operations_runbook.md`에 둔다.

## 12. 관찰 탭

관찰 탭은 Phase 1-B에서 **다시 보기 목록** 수준으로 시작한다.

다시 보기는 매수 후보 목록이 아니라, 사용자가 공개 지표를 보고 한 번 더 확인하고 싶은 기업을 남기는 로컬 목록이다. 관찰 탭의 제품 보상은 `마지막으로 확인한 기준일`과 `새 공개자료 있음`을 통해 사용자가 다시 상세로 들어갈 이유를 보여주는 데 있다.

포함:

- 다시 보기 목록
- 기업명
- 마지막 데이터 기준일
- `새 공개자료 있음` 인앱 점 표시
- 기업 상세 재진입
- 다시 보기에서 직접 제거
- 빈 화면 CTA: `발견 탭에서 다시 볼 기업을 추가해 보세요`

다시 보기는 매수 관심이나 투자 의향이 아니다. 카피는 "저장", "관심 종목", "매수 후보" 대신 `다시 보기`로 통일한다.

운영 정책:

- 상한: 사용자당 50개. Phase 1-B 출시 후 1개월 사용 데이터로 재보정한다.
- 정렬: 추가일 내림차순 고정. `관심도순`·`추천순` 같은 추천 외관을 막기 위해 정렬 옵션을 제공하지 않는다.
- 중복: 동일 기업 재추가 시 신규 항목을 만들지 않고 추가일만 갱신한다.
- 새 공개자료 점 표시 트리거: 다시 보기 추가일 이후 §9.1 조건 #3 정의(`사업보고서·반기보고서·분기보고서 또는 지정 주요사항보고서`)에 해당하는 공시 또는 약한 주의 신호 카테고리 공시가 게재된 경우.
- 점 표시는 사용자가 해당 기업 상세 화면을 1회 열면 해제한다.

외부 푸시, 이메일, SMS, OS-level 앱 아이콘 뱃지는 Phase 1-B에서 제외한다.

## 13. 분석 이벤트와 개인정보 경계

Phase 1-B는 사용자별 투자 관심 프로필을 만들지 않는다. 탐색 성향도 장기 프로필로 저장하지 않는다.

탐색 성향 이벤트는 **첫 방문 세션 퍼널 검증**에만 사용한다. 원천 이벤트는 최대 90일 보존하고, 90일 이후에는 탐색 성향 코드와 익명 디바이스/세션 식별자가 함께 남지 않도록 집계 테이블만 보존한다. 익명 디바이스 단위로 탐색 성향과 조건 카테고리를 장기 누적하는 대시보드는 만들지 않는다.

| 데이터 | 처리 |

## 14. 성공 지표

Phase 1-B는 "성향 기반 종목 추천"이 아니라 **탐색 성향에서 공개 지표 확인까지 이어지는 첫 방문 경험**을 검증한다.

### 14.1 North Star

> **첫 방문 세션에서 사용자가 탐색 관점을 선택하고, 조건을 직접 적용한 뒤, 기업 상세의 공개 지표를 확인하고, 기업 1개 이상을 다시 보기에 추가한 비율**

North Star는 첫 방문 세션 기준으로만 산출한다. 탐색 성향을 익명 디바이스에 장기 누적해 재방문 개인화나 장기 사용자 프로필로 사용하지 않는다.

첫 방문은 익명 디바이스 ID 기준 첫 세션으로 정의한다. §13.1의 `첫 방문 익명 세션 이벤트` 표현도 동일 단위(디바이스 단위의 첫 세션)를 가리킨다. 앱 재설치 시 새 첫 방문으로 간주하며, 광고·트래커 차단 등으로 디바이스 ID가 확보되지 않는 환경은 측정 대상에서 제외한다.

판정 이벤트 순서:

```text
exploration_style_selected
→ condition_selected
→ condition_applied
→ result_viewed
→ company_detail_viewed
→ public_metric_section_reached
→ watchlist_added
```

다시 보기 추가는 투자 의향이 아니라 "한 번 더 들여다볼 기업을 외부화했다"는 행동으로 해석한다.

### 14.2 1차 퍼널

| 지표 | 의미 |
|---|---|
| 탐색 관점 선택률 | 첫 방문 세션에서 탐색 관점 1개를 고른 비율 |
| 관점→조건 선택 전환율 | 탐색 관점 선택 후 조건을 직접 선택한 비율 |
| 조건 적용률 | `이 조건으로 기업 보기`를 누른 비율 |
| 결과 조회율 | 조건 적용 후 기업 결과를 본 비율 |
| 상세 진입률 | 결과 기업 중 1개 이상 상세 진입한 비율 |
| 공개 지표 영역 도달률 | 상세에서 공개 지표, 출처, 기준일 중 2개 이상이 포함된 영역까지 도달한 비율 |
| 다시 보기 추가율 | 상세를 본 기업 중 1개 이상 다시 보기에 추가한 비율 |

`공개 지표 영역 도달`은 상세 화면의 viewport에 공개 지표·출처·기준일 영역이 50% 이상 노출된 상태가 1초 이상 유지된 경우로 정의한다. 뷰포트 크기와 디바이스 유형에 무관하게 동일 정의를 적용한다.

### 14.3 초기 가설치

| 지표 | 초기 가설치 |
|---|---:|
| 탐색 관점 선택률 | 65% 이상 |
| 관점→조건 선택 전환율 | 55% 이상 |
| 조건 적용률 | 45% 이상 |
| 결과 조회 후 상세 진입률 | 35% 이상 |
| 공개 지표 영역 도달률 | 50% 이상 |
| 공개 지표 영역 도달 후 다시 보기 추가율 | 35% 이상 |
| 첫 방문 세션 North Star 완료율 | 12% 이상 |

본 절은 Phase 1-B 측정 지표 카탈로그이며, Gate 2 통과 게이트의 임계 정의는 §20에 둔다. §20에 포함되지 않은 `결과 조회 후 상세 진입률 35% 이상`과 `공개 지표 영역 도달 후 다시 보기 추가율 35% 이상`은 게이트 판정이 아니라 Iteration 1-BR 병목 진단과 정기 모니터링 용도로만 사용한다. 두 지표가 §20 5개 임계와 동시에 미달하면 우선 §20 5개의 미달 원인을 먼저 진단한다.

3rd의 North Star 15%보다 낮게 시작한다. 4th는 탐색 관점 단계가 추가되어 퍼널이 길어지기 때문이다.

초기 가설치는 3rd 문서 내부 테스트 데이터(존재 시)와 입문 투자 앱 일반 추정치를 혼합한 값이다. 3rd 테스트 데이터가 부재한 경우에는 추정치만 기반임을 본 단락에서 가시화한다. 출시 후 1개월 내 실제 데이터로 재보정한다.

### 14.4 정성 인터뷰 성공 기준

첫 사용자 8명 기준:

- 5명 이상이 "무엇부터 봐야 할지 덜 막막했다"고 답한다.
- 5명 이상이 자신이 고른 탐색 관점과 조건의 연결을 자기 말로 설명한다.
- 5명 이상이 공개 지표, 출처, 기준일의 의미를 자기 말로 설명한다.
- 5명 이상이 다시 보기에 추가한 이유를 공개 지표와 연결해 설명한다.
- 2명 이하만 "추천처럼 느껴졌다"고 답한다.

## 15. 법무 리스크 모델

### 15.1 핵심 리스크

4th에서 새로 다루는 핵심 리스크는 **탐색 성향이 개인화 추천처럼 보일 가능성**이다.

법무 검토의 중심 질문:

> "이 제품이 사용자의 성향을 바탕으로 특정 금융투자상품 또는 종목에 대한 투자 판단을 제공하는가?"

제품 구조상 답은 다음이어야 한다.

> "아니다. 성향은 탐색 관점 설명에만 쓰이며, 결과는 사용자가 직접 선택·적용한 공개 조건으로만 산출된다."

### 15.2 출시 차단 사유

다음 중 하나라도 남아 있으면 Phase 1-B 출시를 차단한다.

- 탐색 성향 선택 후 조건이 자동 선택되거나 자동 적용됨
- 탐색 성향 선택 직후 기업 결과가 노출됨
- 결과 정렬에 탐색 성향 가중치가 들어감
- "당신에게 맞는 기업", "성향에 맞는 종목", "추천 종목" 표현이 남아 있음
- 다시 보기가 매수 관심 또는 투자 의향처럼 표현됨
- 서버에 사용자별 탐색 성향·조건·종목 관심 프로필이 저장됨
- 탐색 성향 코드나 조건 카테고리 코드가 익명 디바이스 단위로 장기 누적됨
- 무료 구조에서도 반복적·계속적 투자자문업 해당 가능성이 높다는 외부 법무 판단이 나옴
- DART/OpenDART 또는 거래소 시장조치 데이터 이용 조건 위반 소지가 해소되지 않음

### 15.3 법무 검토 패키지

Phase 1-B 외부 출시 전 다음 항목을 검토한다.

- 첫 진입 탐색 관점 선택 UX
- 탐색 관점 카드 카피
- 탐색 관점과 조건 카드의 연결 방식
- 조건 직접 선택/적용 UX
- 학습형 표시의 기본 펼침 UX
- 결과 카드 문구
- 상세 화면 문구
- `나중에 다시 보기` CTA
- 다시 보기 기능명과 관찰 탭 카피
- 조건 학습 모듈 카피
- 사용자용 룰 설명 페이지
- 결과 정렬 기준
- 익명 이벤트 스키마
- 기기 로컬 저장 정책
- DART/OpenDART 이용 조건
- critical 시장조치 데이터 gate
- 금지 표현 목록
- 디스클레이머

법무 검토 주체는 외부 자문 로펌 1차 판단 + 사내 PM + 사내 법무 책임자 합의로 둔다. 외부 자문 판정을 사내 판단으로 완화하지 않는다.

| **Gate 0** | 빌드 착수 게이트 | 빌드 전 운영 가능성 확인 | DART/OpenDART 이용 조건, critical 시장조치 데이터 필수 세트, 3조건 산식 초안, 탐색 관점 카피 초안, 법무 쟁점 1차 메모 | 미확정 상태의 외부 출시 |
| **Phase 1-A** | 내부 베타 | 탐색 관점→조건 적용→공개 지표 확인 퍼널 검증 | 발견 탭, 탐색 관점 카드, 조건 카드, 결과 카드, 상세, 다시 보기, 룰 설명 페이지, 이벤트 스키마 | 사주 탭, 외부 알림, 유료화 |

| **Iteration 1-BR** | Phase 1-B 개선 루프 | Phase 1-B 지표 미달 원인 개선 | 탐색 관점 카드, 조건 학습 모듈, 결과 카드 문구, 첫 방문 퍼널 개선 | 제품 범위 확장, 사주·가격·계정 기능 추가 |
| **Candidate Experiment 1-C** | 확장 후보 실험 | Gate 2 통과 후 다음 병목 해결 | 1-C-Saju, 1-C-NL, 1-C-Price, 1-C-Observe, 1-C-Account 중 우선순위 1개씩 검토 | 여러 후보 동시 빌드, 사주 기반 종목 추천, AI 종목 검색 |
| **Phase 1.5** | 관찰 강화 | 1-C-Observe 성공 시 다시 보기 이후 재방문 경험 강화 | DART 공시 피드, 공시 유형 설명, IR 캘린더, 외부 알림 법무 게이트 | 알림 게이트 없는 푸시 |
| **BM Gate** | 수익화 전 법무 재검토 | 수익화 가능 여부 판단 | 광고, 구독, 제휴, 리퍼럴, 프리미엄 기능 검토 | 법무 재검토 없는 수익화 |

1-C 후보 실험은 Gate 2 통과 후 `병목`, `가설`, `법무 리스크`, `데이터 준비도`를 기준으로 하나씩 선택한다. 각 후보는 별도 성공·중단 기준을 가진다.

| 후보 | 목적 | 선행 조건 | 성공 기준 | 중단 기준 |
|---|---|---|---|---|
| **1-C-Saju** | 사주 기반 탐색 질문 검증 | Phase 1-B 핵심 퍼널 통과, 사주 법무 게이트 통과 | 사용자가 사주를 종목 추천이 아니라 탐색 질문으로 이해함 | 사주가 종목 적합성·궁합으로 해석되는 비율이 높음 |
| **1-C-NL** | 자연어 조건 입력 검증 | Phase 1-B 핵심 퍼널 통과, 조건 선택 병목 확인, 자연어 입력 법무·개인정보 게이트 통과 | 사용자가 문장을 기존 공개 지표 조건 후보로 바꾸는 기능으로 이해함 | 사용자가 AI 종목 검색·추천·투자 상담으로 이해함 |
| **1-C-Price** | 가격 변동 조건 검토 | KRX/시장 데이터 이용 조건 확인, 가격 변동 표현 법무 검토, 투자 신호 오해율 검증 | 가격 변동 조건이 공개 사실 확인으로 이해됨 | 가격 변동이 매매 타이밍·상승 신호로 해석됨 |
| **1-C-Observe** | 관찰 루프 강화 | 다시 보기 재방문 수요 확인 | 다시 보기 사용자가 새 공개자료 확인을 위해 재방문함 | 재방문 이유가 투자 신호 알림 기대에 집중됨 |
| **1-C-Account** | 계정/동기화 검토 | 로컬 저장 한계가 실제 병목으로 확인됨 | 계정 필요가 기기 변경·백업 문제로 명확히 확인됨 | 계정이 사용자별 관심 종목 프로필로 해석될 위험이 큼 |

**Gate 0 보강** — critical 시장조치 데이터 필수 세트의 확보 판정 기한은 2026-06-30이다. 미확보 시 §9.2의 분기(`Phase 1-A 진입 보류` 또는 `critical 제외 약속을 제거한 별도 제품 정의로 법무 재검토`)가 발동되며, 이 경우 4th 본문 §1·§9 재작성이 필요하다. 책임자는 **신현준(PM·기획 단독, 본 문서 작성자, 2026-05-28 commit)** 이다. PM 책임자 변경 시 v2.x bump와 함께 본 단락을 갱신한다. 책임자가 부재한 상태로 변경되면 Gate 0 진입을 즉시 보류한다.

**Gate 1 보강** — Phase 1-A는 다음 조건을 모두 만족할 때 Gate 1 검토로 이동할 수 있다.

- 내부 베타 사용자 10명 이상
- 핵심 퍼널을 처음부터 끝까지 완주한 세션 1건 이상
- 금지 표현 수동 검수 pass (검수 책임자: 사내 법무 책임자). 자동 lint 도구는 별도 운영 부속서 `forbidden_phrase_lint.md`에서 다룬다.
- 화면 상태 명세서 초안 존재

4th 문서는 **제품 방향 PRD**다. 외부 출시 가능한 PRD로 전환하기 전에는 3rd에서 정의한 critical 데이터 gate 세부 판정표, 비상 운영 정책, DART 면책 상세, 내부 룰 audit 샘플 기준, 법무 출시 체크리스트, 화면 상태 명세서를 별도 운영 부속서로 붙여야 한다.

## 19. 자동 결정 로그

1. **Phase 1의 중심을 무엇으로 둘 것인가?** → **탐색 성향 기반 기업 알아보기로 둔다.** 원래 제품의 감각을 회복하되 종목 추천으로 해석되는 구조는 피한다.
2. **성향은 어디까지 사용할 것인가?** → **탐색 관점 선택과 조건 이해에만 사용한다.** 사람과 종목을 매칭하지 않으면 법무 리스크를 낮추면서도 사용자 효용을 살릴 수 있다.
3. **첫 화면은 조건 카드인가, 성향 카드인가?** → **탐색 관점 카드로 시작한다.** 초보자의 첫 질문은 "어떤 조건을 고를까"보다 "무엇부터 봐야 할까"에 가깝다.
4. **탐색 관점이 조건을 자동 선택하는가?** → **아니다.** 자동 선택은 개인화 추천 외관을 만들 수 있으므로 사용자가 직접 선택해야 한다.
5. **탐색 관점 선택 직후 결과를 보여주는가?** → **아니다.** 결과는 반드시 `이 조건으로 기업 보기` 이후에만 노출한다.
6. **Phase 1-B 조건 수는 유지하는가?** → **3개 조건 + 1개 상태 정보로 유지한다.** 제품 방향은 바꾸되 데이터·법무 복잡도는 늘리지 않는다.
7. **약한 주의 신호는 조건인가?** → **아니다. 상태 정보로만 표시한다.** 사용자가 위험/안전 판단으로 오해하지 않도록 조건 토글에서 제외한다.
8. **정렬에 성향을 반영하는가?** → **아니다. 기준일 최신순과 거래 규모 기준만 사용한다.** 성향 정렬은 "맞춤 추천"처럼 보일 수 있다.
9. **다시 보기는 어떤 의미인가?** → **한 번 더 들여다볼 기업의 임시 목록이다.** 매수 관심이나 투자 의향으로 해석하지 않는다.
10. **탐색 성향은 서버에 저장하는가?** → **아니다. 익명 세션 이벤트로만 집계한다.** 장기 프로필은 개인화 추천 외관과 개인정보 리스크를 만든다.
11. **종목 ID를 사용자 행동 이벤트에 저장하는가?** → **아니다.** 사용자별 종목 관심 이력을 만들지 않기 위해 이벤트에서 제외한다.
12. **룰 품질은 어떻게 검증하는가?** → **사용자 이벤트와 분리된 내부 배치 리포트로 검증한다.** 제품 분석과 종목 단위 검증을 분리해야 개인정보·추천 리스크를 줄일 수 있다.
13. **사주는 Phase 1-B에 포함하는가?** → **아니다. 조건부 확장 후보로만 둔다.** 지금의 본류는 탐색 성향과 공개 지표 확인이다.
14. **외부 알림은 Phase 1-B에 포함하는가?** → **아니다.** 반복적·계속적 종목 통지로 해석될 수 있으므로 별도 알림 법무 게이트 이후 검토한다.
15. **수익화는 언제 검토하는가?** → **Phase 1-B 출시 후 별도 BM Gate에서 검토한다.** 무료 구조에서도 자문업 리스크가 사라지지 않으므로 수익화 전 재검토가 필요하다.
16. **North Star는 무엇인가?** → **탐색 관점 선택→조건 적용→공개 지표 확인→다시 보기 추가 완료율이다.** 새 방향의 핵심 경험 전체를 검증해야 한다.
17. **법무 검토의 새 핵심 쟁점은 무엇인가?** → **탐색 성향이 개인화 추천으로 보이는지 여부다.** 4th의 가장 큰 변경점이므로 별도 출시 차단 기준을 둔다.
18. **문서의 성격은 어떻게 바꾸는가?** → **방어 문서가 아니라 제품 방향 문서로 선명하게 만든다.** 법무 가드는 유지하되 첫 2페이지에서는 사용자가 느낄 변화와 제품 감각을 먼저 보여준다.
19. **탐색 관점은 몇 개로 시작하는가?** → **3개 탐색 관점으로 시작한다.** 모두 "무엇을 먼저 볼 것인가"에 해당해야 같은 레벨의 선택지가 된다.
20. **`설명부터 천천히 보기`는 어디에 두는가?** → **탐색 관점에서 제외하고 첫 방문 학습형 표시로 둔다.** 이는 볼 관점이 아니라 설명을 보여주는 방식에 가깝기 때문이다.
21. **탐색 관점과 조건의 연결 표현은 무엇으로 쓰는가?** → **`함께 읽어볼 조건`으로 쓴다.** `연결되는 기본 조건`은 조건 추천처럼 보일 수 있으므로 낮춘다.
22. **평가성 변화 카피는 어떻게 낮추는가?** → **`좋아졌는지/나빠졌는지`와 `성장 방향`을 `늘었는지/줄었는지`와 `증감 방향`으로 바꾼다.** 공개 지표의 변화 확인으로 의미를 제한하기 위해서다.
23. **탐색 성향 이벤트는 얼마나 보존하는가?** → **원천 이벤트는 최대 90일 보존하고, 이후에는 탐색 성향 코드와 익명 식별자가 결합된 데이터를 남기지 않는다.** 장기 성향 프로필 외관을 막기 위해서다.
24. **4th는 외부 출시 가능한 최종 PRD인가?** → **아니다. 제품 방향 PRD이며, 외부 출시 전 3rd의 운영 안전장치를 별도 부속서로 붙인다.** 방향성 문서와 출시 운영 문서를 혼동하지 않기 위해서다.
25. **사용자 사주는 다시 넣을 수 있는가?** → **1-C-Saju 후보 실험으로만 검토한다.** 사용자 사주는 개인화 추천 외관을 만들 수 있으므로 Phase 1-B 본류에는 넣지 않는다.
26. **사주가 추천하는 대상은 무엇인가?** → **종목이 아니라 탐색 기준이다.** `나와 맞는 기업`이 아니라 `오늘의 탐색 질문`으로 제한해야 법무 리스크와 제품 효용의 균형을 맞출 수 있다.
27. **사주가 조건을 자동 선택하거나 적용하는가?** → **아니다.** 조건 자동 선택은 사주가 결과 산출에 개입했다는 외관을 만든다.
28. **사주가 결과 산출·정렬·다시 보기에 영향을 주는가?** → **아니다.** 사주는 질문 생성에만 쓰고, 결과는 사용자가 직접 켠 공개 지표 조건으로만 산출한다.
29. **사주 입력값은 어떻게 저장하는가?** → **서버에 저장하지 않는다.** 생년월일시와 사주 계산 결과는 온디바이스·세션 단위 임시값으로 처리하는 것을 기본값으로 둔다.

30. **Phase와 Gate는 어떻게 구분하는가?** → **Phase는 제품 범위 변화, Gate는 단계 통과 판단, Iteration은 동일 범위 개선, Candidate Experiment는 확장 후보 실험으로 구분한다.** 출시 단계와 검증 조건을 섞지 않아야 로드맵 판단이 선명해진다.
31. **Phase 1-B 지표 미달 시 다음 단계로 넘어가는가?** → **아니다. Iteration 1-BR에서 핵심 경험을 먼저 개선한다.** 지표 미달 상태의 확장 빌드는 병목을 가릴 수 있다.
32. **Phase 1-C는 정식 출시 단계인가?** → **아니다. Gate 2 통과 후 선택 가능한 후보 실험 묶음이다.** 사주, 가격, 관찰, 계정은 리스크와 검증 방식이 다르므로 하나의 Phase로 묶지 않는다.
33. **Phase 1.5는 언제 진입하는가?** → **1-C-Observe가 성공했을 때 관찰 강화 Phase로 승격한다.** 관찰 루프 후보 실험과 정식 관찰 강화 단계를 구분하기 위해서다.
34. **가격 변동 조건은 무엇을 통과해야 하는가?** → **KRX/시장 데이터 이용 조건, 가격 변동 표현 법무 검토, 투자 신호 오해율 검증을 모두 통과해야 한다.** 가격 변동 조건은 투자 신호처럼 보일 수 있으므로 라이선스 확인만으로는 부족하다.
35. **자연어 입력 기능은 넣을 수 있는가?** → **1-C-NL 후보 실험으로만 검토한다.** Phase 1-B 본류에 넣으면 조건 직접 선택 퍼널의 효과와 AI 입력 보조의 효과를 분리하기 어렵다.
36. **자연어 입력은 무엇을 산출하는가?** → **종목이 아니라 기존 공개 지표 조건 후보를 산출한다.** 사람-종목 매칭을 만들지 않아야 개인화 추천 외관을 낮출 수 있다.
37. **자연어 입력 후 결과를 바로 보여주는가?** → **아니다. 조건 후보만 보여주고 사용자가 직접 선택·적용해야 한다.** 결과 자동 노출은 조건 자동 적용과 같은 추천 외관을 만든다.
38. **종목명·종목코드·기업명이 입력되면 어떻게 하는가?** → **조건 변환을 중단하고 기업명 기반 요청으로 차단한다.** 특정 기업 질의와 조건 입력 보조가 섞이면 AI 종목 검색으로 이해될 수 있다.
39. **금지 의도와 허용 조건이 섞인 자연어 입력은 어떻게 처리하는가?** → **전체 차단한다.** 허용 조건만 추출하면 `안전한`, `살 만한` 같은 금지 의도를 우회할 수 있다.
40. **자연어 입력 원문은 저장하는가?** → **저장하지 않는다.** 원문에는 종목명, 투자 의도, 개인정보성 문장이 섞일 수 있으므로 이벤트와 로그에서 제외한다.
41. **외부 LLM fallback은 언제 허용하는가?** → **zero-retention 또는 API 로그 비저장 조건과 전송 전 민감 토큰 차단이 확인된 경우에만 허용한다.** 이 조건을 만족하지 못하면 룰 기반만 출시한다.
42. **1-C-NL은 다른 1-C 후보와 동시에 출시하는가?** → **아니다. 조건 선택 병목이 확인될 때만 단독 후보 실험으로 검토한다.** 여러 후보를 동시에 붙이면 어떤 병목을 해결했는지 판단하기 어렵다.

43. **약한 주의 신호 카테고리를 본문에 어디까지 적는가?** → **§9.1에 정의 한 단락 + 본문 예시 3개를 둔다.** 전체 enumeration은 운영 부속서로 미루되 본문에 정의가 없으면 critical과의 경계가 작동하지 않는다.
44. **critical 시장조치 데이터 확보 판정은 언제 끝내는가?** → **2026-06-30까지로 박는다.** 미정 상태로 두면 Gate 0 진입 자체가 무한 지연된다.
45. **첫 1개 조건 제약의 의도는 무엇인가?** → **조건의 의미를 한 개씩 학습시키기 위함이다.** 0개 결과 회피 목적이 아님을 본문에 명시해야 디자인 결정이 흔들리지 않는다.
46. **재방문 사용자의 발견 탭 경험은 어떻게 정의하는가?** → **§8.7로 별도 절을 둔다.** 첫 방문과 재방문은 측정 단위가 다르므로 같은 절에 묶으면 정책이 혼동된다.
47. **데이터 갱신 지연 시 카드 표시는 어떻게 하는가?** → **`기준일 확인 지연` 보조 상태로 표시한다.** 약한 주의 신호 외 조건에도 동일 표시를 사용해 일관성을 유지한다.
48. **0개 결과 가이드는 어떤 카피로 표시하는가?** → **`조건을 줄여 다시 적용해 보세요` 고정 카피만 표시한다.** 양적 지정이나 어떤 조건을 끄라는 가이드는 추천 외관을 만든다.
49. **다시 보기 운영 정책의 핵심 파라미터는 무엇인가?** → **상한 50개(재보정 대상), 추가일 내림차순 고정, 점 표시 트리거는 §9.1 조건 #3 정의와 약한 주의 신호 카테고리 공시다.** 본문 조건 정의와 동일 데이터 소스를 써야 파이프라인이 일관된다.
50. **정보 오류 신고는 본문에 어디까지 적는가?** → **경계와 우선순위(DART 원문 우선)만 본문에 적고 운영 흐름은 부속서로 위임한다.** 본문은 사용자 약속 영역, 운영 흐름은 부속서 영역이다.
51. **Phase 1-A 통과 기준을 어떤 형태로 두는가?** → **정량(사용자 10명, 완주 1건) + 정성(수동 검수 pass, 명세서 초안) 혼합이다.** Gate 2가 정량 중심이라 Gate 1도 동일 패턴을 따라야 게이트 운영이 균질해진다.
52. **첫 방문의 측정 단위는 무엇인가?** → **익명 디바이스 ID 기준 첫 세션이다.** 세션 ID 기준은 동일 사용자가 여러 번 첫 방문이 되어 측정이 불안정해진다.
53. **LLM fallback sign-off 주체는 누구인가?** → **외부 자문 로펌, 사내 법무 책임자, 데이터 처리 책임자(DPO 부재 시 사내 법무 책임자 겸임) 3자다.** 한 주체에게 맡기면 §15.3 외부 자문 우선 원칙과 충돌한다.
54. **공개 지표 영역 도달은 어떻게 측정하는가?** → **viewport 50% 노출 + 1초 dwell이다.** 단순 진입 이벤트는 스크롤 통과만으로 발화하므로 도달 신호로 부적합하다.
55. **정량 가설치 도출 근거는 어디에 적는가?** → **§14.3에 메모 한 단락으로 적는다.** 출처를 별도 문서로 분리하면 Gate 2 판정 시점에 근거가 분실될 위험이 있다.
56. **학습형 표시 닫힌 상태는 어디까지 유지하는가?** → **동일 디바이스의 동일 앱 설치 세션 내에서만 유지한다.** 디바이스 변경·재설치 시 다시 펼침으로 일관성을 가져간다.
57. **금지 표현 lint 도구는 어디에서 다루는가?** → **운영 부속서 `forbidden_phrase_lint.md`에서 다룬다.** 본문은 표현 결정 영역, 자동 검증은 인프라 영역으로 분리한다.

## 20. Gate 2: Phase 1-B 학습 게이트

Phase 1-B는 다음 조건을 모두 만족하면 Candidate Experiment 1-C 검토로 이동할 수 있다. Phase 1.5는 1-C-Observe 후보 실험이 성공했을 때만 관찰 강화 단계로 승격한다.

- 탐색 관점 선택률 65% 이상
- 관점→조건 선택 전환율 55% 이상
- 조건 적용률 45% 이상
- 공개 지표 영역 도달률 50% 이상
- 첫 방문 세션 North Star 완료율 12% 이상
- 정성 인터뷰에서 첫 사용자 8명 중 5명 이상이 "무엇부터 봐야 할지 덜 막막했다"고 답함
- 첫 사용자 8명 중 5명 이상이 자신이 확인한 공개 지표와 기준일을 자기 말로 설명함
- 첫 사용자 8명 중 2명 이하만 "추천처럼 느껴졌다"고 답함
- 외부 법무 검토에서 탐색 성향 UX가 개인화 종목 추천으로 해석될 가능성이 출시 차단 수준이 아니라고 판정됨

위 조건을 만족하지 못하면 Candidate Experiment 1-C로 넘어가지 않고 Iteration 1-BR에서 탐색 관점 카드, 조건 학습 모듈, 결과 카드 문구를 먼저 반복 개선한다.

Candidate Experiment 1-C 검토 시 Phase 1-B 병목이 `조건 선택 어려움`으로 확인되면 1-C-NL을 우선 후보로 둘 수 있다. 이 경우 자연어 입력 법무·개인정보 게이트, 금지 표현 테스트, 조건 매핑 정확도 90% 이상, 투자 판단·추천·가격 예측·안전성 판단 요청 차단 정확도 95% 이상을 통과해야 한다.
