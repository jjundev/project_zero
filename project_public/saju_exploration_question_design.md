# Design: 사주 기반 탐색 기준 추천

사용자의 사주는 종목을 추천하거나 기업과 궁합을 계산하는 데 쓰지 않는다. 사주는 사용자가 기업을 볼 때 던질 첫 질문, 즉 탐색 기준을 고르는 참고 장치로만 사용한다. 기업 결과는 기존과 동일하게 사용자가 직접 선택한 공개 지표 조건으로만 산출되며, 사주는 결과 산출·정렬·다시 보기 구성에 영향을 주지 않는다.

## Architecture / Decisions

### 제품 정의

이 기능의 한 줄 정의는 다음과 같다.

> **"사용자의 사주로 종목을 고르는 것이 아니라, 오늘 기업을 볼 때 던질 첫 질문을 정하는 기능"**

사용자는 생년월일시를 입력할 수 있다. 앱은 이를 바탕으로 `오늘의 탐색 질문` 1개를 보여준다. 이 질문은 특정 기업, 업종, 종목, 가격, 매매 시점, 수익 가능성과 연결하지 않는다.

허용되는 구조:

```text
사용자 사주
→ 오늘의 탐색 질문
→ 사용자의 조건 직접 선택
→ 공개 지표 기반 결과
```

금지되는 구조:

```text
사용자 사주
→ 사용자와 맞는 업종·기업·종목
→ 사주 궁합 점수 또는 추천 결과
→ 투자 판단으로 해석되는 문장
```

### 사용자 흐름

Phase 1-C 후보 실험의 기본 흐름은 다음과 같다.

```text
발견 탭 진입
→ 오늘의 탐색 질문으로 시작하기 선택
→ 생년월일시 입력
→ 온디바이스에서 탐색 질문 생성
→ "오늘은 [질문]부터 확인해 보세요" 표시
→ 조건 카드는 0개 선택 상태로 표시
→ 사용자가 조건을 직접 선택
→ 이 조건으로 기업 보기
→ 현재 켠 조건에 해당하는 기업 표시
```

사주 입력 후에도 조건은 자동 선택하지 않는다. 결과 영역도 자동 노출하지 않는다. 사용자가 조건을 선택하고 `이 조건으로 기업 보기`를 눌러야만 기업 결과가 표시된다.

### 탐색 질문 세트

Phase 1-C 실험에서는 사주 해석을 금융 판단으로 번역하지 않고, 기존 공개 지표 조건과 연결 가능한 질문으로만 변환한다.

| 질문 코드 | 사용자 문장 | 연결 가능한 조건 | 금지되는 해석 |
|---|---|---|---|
| `profit_first` | "최근 손익 흐름을 먼저 확인해 보세요" | 최근 영업이익 흑자 여부 | 수익 가능성, 안전한 기업 |
| `change_first` | "최근 늘었는지 줄었는지 먼저 확인해 보세요" | 매출 또는 영업이익 증가 확인 | 성장주 추천, 좋은 기업 |
| `filing_first` | "새로 확인할 공개자료가 있는지 먼저 읽어보세요" | 최근 확인할 주요 공개자료 | 호재 공시, 긍정 신호 |

질문 문장은 1개만 보여준다. 여러 질문을 점수화하거나 순위를 만들지 않는다. 특정 질문이 표시되어도 연결 조건은 자동 선택하지 않는다.

### 알고리즘 경계

사주 알고리즘은 `saju_to_exploration_question`으로만 존재한다.

```text
birth_datetime
→ saju_profile_ephemeral
→ exploration_question_code
```

허용:

- 생년월일시로 오늘의 탐색 질문 1개 생성
- 질문과 함께 읽어볼 수 있는 조건 설명 표시
- 조건 카드의 설명 순서 조정 검토
- 온디바이스 계산
- 세션 단위 임시값

금지:

- 종목 결과 산출에 사주 사용
- 기업 정렬에 사주 사용
- 조건 자동 선택
- 조건 자동 적용
- 업종 추천
- 기업별 사주 궁합 점수
- 사주와 다시 보기 목록 결합
- 사주와 종목 조회 이력 결합
- 서버에 생년월일시 또는 사주 코드 저장

### UX 문구

핵심 안내 문구:

> "사주로 종목을 고르지 않습니다. 오늘 기업을 볼 때 던질 첫 질문을 정합니다."

허용 표현:

- 오늘의 탐색 질문
- 오늘은 이 질문으로 기업을 읽어보세요
- 먼저 확인할 공개 지표
- 함께 읽어볼 수 있는 조건
- 사주는 종목 추천이나 투자 판단에 사용되지 않습니다

금지 표현:

- 당신의 사주와 잘 맞는 기업
- 사주 추천 종목
- 재물운 종목
- 금전운이 좋은 기업
- 궁합이 좋은 종목
- 오늘 사야 할 종목
- 사주상 유리한 업종
- 오행에 맞는 기업

### 개인정보와 분석

생년월일시와 사주 계산 결과는 서버에 저장하지 않는다. 가능하면 온디바이스에서 계산하고, 세션 종료 시 삭제한다. 분석 이벤트에는 사주 원본값, 사주 코드, 오행 코드, 생년월일시, 종목 ID를 포함하지 않는다.

허용 이벤트:

```text
saju_question_started
saju_question_generated
saju_question_dismissed
condition_selected
condition_applied
result_viewed
```

허용 이벤트 속성:

- 질문 생성 완료 여부
- 사용자가 조건을 직접 선택했는지 여부
- 선택한 조건 개수
- 결과 개수 구간: `0`, `1_3`, `4_plus`

금지 이벤트 속성:

- 생년월일시
- 사주 원국 또는 오행 코드
- 사주 기반 질문 코드와 익명 디바이스의 장기 결합값
- 종목명
- 종목 코드
- 사주와 다시 보기 종목의 결합 정보

### 출시 게이트

이 기능은 Phase 1-B에 포함하지 않는다. Phase 1-B의 탐색 관점→조건 직접 선택→공개 지표 확인 퍼널이 검증된 뒤, Phase 1-C 후보 실험으로만 검토한다.

출시 전 필수 게이트:

- 외부 법무 검토에서 사주 기반 탐색 질문이 개인화 종목 추천으로 해석되지 않는지 확인
- 생년월일시 온디바이스 처리 가능성 확인
- 사주 입력값과 종목 행동 이벤트가 결합 저장되지 않는지 확인
- UX에서 조건 자동 선택·자동 적용·결과 자동 노출이 없는지 확인
- 금지 표현이 화면, 이벤트명, 내부 변수명에 남아 있지 않은지 확인

## Decision log

1. **사주를 제품에 다시 넣을 것인가?** → **Phase 1-C 후보 실험으로만 넣는다.** Phase 1-B의 핵심 퍼널을 먼저 검증해야 하며, 사주는 별도 법무 게이트가 필요한 고위험 확장이다.
2. **사주가 추천하는 대상은 무엇인가?** → **종목이 아니라 탐색 기준이다.** 사용자 사주와 특정 금융상품을 연결하면 개인화 추천처럼 보일 가능성이 크다.
3. **탐색 기준은 어떤 형태로 보여줄 것인가?** → **`오늘의 탐색 질문` 1개로 보여준다.** 질문은 사용자가 직접 조건을 고르기 전의 출발점으로 작동하며 결과를 만들지 않는다.
4. **사주가 조건을 자동 선택하는가?** → **아니다.** 자동 선택은 사용자의 사주가 결과 산출에 개입했다는 외관을 만든다.
5. **사주가 조건 카드 순서에 영향을 줄 수 있는가?** → **실험 후보로만 둔다.** 순서 조정도 추천 외관을 만들 수 있으므로 법무 검토 전에는 설명 문구 연결까지만 허용한다.
6. **사주가 기업 결과 산출에 영향을 주는가?** → **아니다.** 결과는 사용자가 직접 켠 공개 지표 조건으로만 산출되어야 한다.
7. **사주가 기업 정렬에 영향을 주는가?** → **아니다.** 정렬은 기준일 최신순, 거래 규모 등 기계적 기준으로만 설명 가능해야 한다.
8. **사주와 업종을 연결할 것인가?** → **연결하지 않는다.** 업종 연결은 사실상 투자 대상군 추천으로 보일 수 있다.
9. **사용자 사주를 서버에 저장할 것인가?** → **저장하지 않는다.** 생년월일시는 개인화와 장기 프로필 리스크를 동시에 키운다.
10. **사주 계산은 어디서 수행하는가?** → **온디바이스 계산을 기본값으로 둔다.** 원본 입력값을 서버로 보내지 않는 편이 개인정보와 추천 외관 리스크를 낮춘다.
11. **분석 이벤트에 사주 코드를 남길 것인가?** → **남기지 않는다.** 익명 디바이스와 결합된 사주 코드는 장기 개인화 프로필처럼 해석될 수 있다.
12. **카피의 핵심 문장은 무엇인가?** → **"사주로 종목을 고르지 않고, 오늘 기업을 볼 때 던질 첫 질문을 정합니다."** 사용자가 기능의 경계를 즉시 이해해야 한다.
13. **금지 표현의 중심은 무엇인가?** → **`맞는 기업`, `추천 종목`, `재물운`, `궁합`, `오행에 맞는 업종`이다.** 이 표현들은 사주와 투자 판단을 직접 연결한다.
14. **기존 탐색 관점과의 관계는 무엇인가?** → **사주는 탐색 관점을 대체하지 않고 진입 옵션으로만 둔다.** 기존의 3개 탐색 관점은 사주 없이도 독립적으로 작동해야 한다.
15. **성공 여부는 무엇으로 판단하는가?** → **질문 생성 후 조건 직접 선택률과 공개 지표 도달률로 판단한다.** 특정 종목 클릭률이나 다시 보기 종목의 성과로 판단하지 않는다.

## Termination

Converged after 15 decisions.
