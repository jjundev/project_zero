# boss-reply — 사장님 카톡 답장 생성

사장님이 보낸 카톡 메시지(텍스트 또는 스크린샷)를 입력받아, **사장님 성향에 최적화된 답장 초안(말풍선) + 근거**를 만든다. 이 스킬은 답을 *대신 결정*하지 않는다 — 현준(사용자)이 보낼 초안을 짓고, 왜 그렇게 짰는지 설명한다.

> 핵심 철학: 사장님은 **표면 문장이 아니라 진짜 의중**을 읽어주길 원하고, **본질 → 가르침 귀속 → 자기 입장** 순서로 또렷한 답을 좋아한다. 빈 칭찬·뜸·무입장 보류는 약하게 읽힌다.

---

## When to use

**발동**:
- `/boss-reply` 명시 호출.
- 사장님 카톡(텍스트·스크린샷)을 붙이며 "뭐라고 답하지 / 답장 만들어줘 / 이거 답변" 요청.
- 직전 boss-reply 답에 대해 "더 짧게 / 다르게 / 의도가 다를 수도" 후속.

**발동하지 말 것**:
- 사장님과 무관한 대화, 다른 사람과의 카톡.
- 답장이 아니라 *내용 자체를 결정·토론·기획*하려는 경우(그땐 일반 대화로).
- 프로젝트(사주·주식앱, 야호, AI 참모진) 자체를 설계·구현하는 작업.

---

## Inputs

다음을 종합해 해석:
1. 사장님 메시지 **텍스트**.
2. 카톡 **스크린샷 이미지**(Read로 읽음).
3. 직전 **대화 맥락**(이전 말풍선·이번 세션 흐름).

입력이 불명확하면 한 줄로 "어떤 메시지에 답할까?" 묻고 대기. 지어내지 않는다.

## 1단계 — 메시지 파싱

사장님의 **실제 발화만** 추출한다(여러 말풍선이면 묶어서 한 덩어리로 읽기).

**스크린샷 화자 판별**(색만 믿지 말 것):
- **정렬**: 좌측 = 상대(사장님), 우측 = 나(현준).
- **발신자 라벨**: "사장님" 이름표가 붙은 쪽.
- **색**: 보통 사장님=회색/흰색 말풍선, 현준=노랑.
- 셋이 **엇갈리면**(테마·스킨 변동) 추측하지 말고 한 줄로 "왼쪽 회색이 사장님 맞죠?" 확인.

오타·STT 흔적(예: "만ㄷㄹ어", "햐보니")은 보정해 **진의**를 잡는다.

## 2단계 — Register 판별 (톤 결정)

메시지가 어느 모드인지 먼저 정한다. **모드가 톤을 지배한다.**

| 모드 | 신호 | 답 톤 |
|---|---|---|
| **감정/애정/신뢰** | "잘 부탁한다", 비전·관계 표현("적당한 거리", "선물 받는 듯") | **짧게·진심.** 분석·질문·개선안 끄기. 본질 1번 되비추고 담담한 다짐으로 받기 |
| **분석/질문** | "왜?", "어땠어?", "근거가 뭐야", "어떠냐" | **다요인 근거 + 경험 프레이밍 + 가르침 귀속 + 구체적 자기 입장** |
| **자랑/공유** | 본인 산출물 제시("직접 만든 거 어때", 캡처 보여줌) | **구체적 인정(빈 칭찬 X) + 본질 짚기 + 동지애** |
| **소크라테스 추궁** | 꼬리 "왜?"로 근거·사고과정 캐물음 | **정면으로 근거 제시.** 회피·뜸·무입장 보류 금지 |

> 모드가 섞이면(예: 자랑+질문) 주된 모드를 잡되, 감정 모드가 조금이라도 깔려 있으면 **분석을 앞세우지 말 것**.

## 3단계 — 의도 해석

표면 문장이 아니라 **진짜 의중**을 읽는다. 프로젝트 메모리와 교차 참조.
- 예: "AI 쓰는 구조 어땠나" = (단순 AI 도구가 아니라) **project_ai_council의 참모진 구조**를 직접 돌려본 소감을 묻는 것.
- 예: "내 경험이 너에게 좋은 영향을 줘야 할 텐데" = 걱정 표현이자 #2(휘둘리지 마라)의 뒷면 → 안심 + 주체성 증명을 원함.

**의도가 애매하면**:
1. 가능한 의도 **2~4개**를 현준에게 제시.
2. 가장 유력한 것 + 근거를 추천.
3. **의도가 갈려도 안전한 답** 제시 — 입장(소감/근거)을 먼저 깔고, 의심되는 깊은 의도를 *부드럽게 짚어* 사장님이 확인/교정하게. (이게 사장님 #4 "본질·의중 읽기"에 점수를 딴다.)

## 4단계 — 성향 렌즈 매핑

`boss-personality.md`의 8렌즈 중 이 메시지에 걸리는 것을 골라 답의 모양을 정한다. (원본이 권위 — 아래는 요약)

1. 소크라테스식 "왜?" — 결론보다 근거·사고과정.
2. 독립적 사고 — "휘둘리지 마라, 네가 정의 내려라, 크로스 체킹".
3. 글로 적힌 명료함 신뢰.
4. 본질/정체성으로 사고 — "이게 뭐다"를 먼저.
5. 경험·학습 > 돈(수사적).
6. 자기 예측 적중 자부심 — 맞히면 인정해주면 좋아함.
7. 좋은 추론엔 즉시 따뜻한 칭찬 + 자기 이론(도미노 파동·우상향·독점기술) 신나서 덧붙임.
8. 감정 열 때(애정·비전·신뢰)는 분석 끄고 짧게 진심. 그가 이름 붙인 개념("사고에 힘", "적당한 거리", "흔들리지 않는 기준점") honor.

**잘 통하는 답**: 다요인 근거 + 경험 프레이밍 + 사장님 가르침에 귀속 + 구체적 자기 마감/입장.
**싫어하는(약하게 읽히는) 답**: 정체성 질문에 과정/일정으로 답, 뜸들이기·회피, 입장 없이 보류, **마음 여는 순간에 분석으로 받기**, 빈 칭찬.

## 5단계 — 답 작성

**기본 골격(분석/질문·자랑 모드)**:
`본질 한 문장 → 사장님 이론/가르침에 귀속 → 구체적 자기 입장`

**감정 모드 골격**: `본질 한 번 되비추기(공감) → 담담한 다짐/상호성`. (근거 나열·질문·개선안 금지)

**형식**:
- 카톡 **말풍선 2~4개**(감정 모드는 2~3개로 더 짧게). 각 말풍선은 `>` 인용블록.
- 자연스러운 **캐주얼 존댓말**(현준이 연하). ㅎㅎ/ㅋㅋ 적당히. 이모지 최소(🙏 정도).
- 사장님이 이름 붙인 개념·표현은 **그대로 받아서** 쓴다(미러링).

**길이 모드**:
- 기본 = 2~4 말풍선.
- "간단히/짧게" 요청 = 1~2 말풍선 + 필요시 **한 줄 초압축 버전**도 같이.

**호칭**: 기본 **"사장님"**. 감정 모드가 깊고 사장님이 스스로 "삼촌"이라 칭했을 때만 "삼촌" 미러링 허용.

## 6단계 — Self-check (출력 전 의무)

- [ ] register에 톤이 맞나 — **감정 모드인데 분석/질문/개선안으로 받지 않았나**.
- [ ] 표면이 아니라 **진짜 의도**에 답했나 / 애매하면 의도 후보를 제시했나.
- [ ] **본질 한 문장**이 있나 / 입장 없이 보류하지 않았나.
- [ ] 사장님 가르침·이론에 **귀속**했나 / 빈 칭찬이 아니라 구체적 근거인가.
- [ ] 말풍선 톤·길이가 자연스럽나 / "간단히" 요청을 반영했나.

하나라도 미충족 → 재작성.

## 출력 포맷

1. **보낼 답** — `>` 말풍선 2~4개.
2. (의도 애매 시) **의도 후보 + 추천** — 짧게.
3. **왜 이렇게 (요약)** — 성향 렌즈에 묶은 3~5줄 근거.
4. (해당 시만) **메모리 업데이트 권장** — 사장님이 새 사실/정체성을 드러냈을 때 한 줄 제안. *자동 기록은 하지 않는다, 제안만.*

## Reference examples (이번 프로젝트에서 반응이 검증된 골드 샘플)

### A. 분석/질문 모드 — 사장님 "왜? 놀랐어"
> 보통 "스스로 생각해라"는 말로 끝나잖아요, 잔소리로. 근데 사장님은 그 사고(思考)를 화면으로 박제해놓으셨더라고요. 추상적인 철학을 사람이 만지는 질문 UI로 바꿔놓은 그 점프가 놀라웠어요.

> 그리고 화면들이 따로 안 놀고 서사 → 돈 → 뉴스 한 줄기로 꿰여 있어서, 사장님 머릿속 모델이 통째로 들어가 있는 게 보이더라고요.

*왜*: "왜?"에 본질(추상→구체 점프)로 정면 응답 + 놀란 이유 다요인 분해 + 그가 외친 "사고에 힘"을 제품의 무기로 격상(귀속).

### B. 감정 모드 — 사장님 "적당한 거리네 힘! 잘 부탁한다 현준아"
> 사장님… 이 말씀은 한참 곱씹게 되네요.

> '적당한 거리' 맞아요. 부모가 대놓고 "세상 이렇더라" 하면 잔소리로 튕기는데, 한 다리 건너 도구로 건네면 그제야 들리잖아요. 제가 만드는 게 그 거리라고 생각하니까 무게가 다르게 느껴져요.

> 근데 저도 이거 만들면서 세상 읽는 법을 배우는 중이라 받은 게 더 많아요. 허투루 안 만들게요. 잘 부탁드립니다 🙏

*왜*: 분석 끄고 짧게. 그가 만든 단어 "적당한 거리" 되비추기 + 담담한 다짐 + 상호성. 근거 나열·질문 없음.

### C. 의도 애매 — 사장님 "AI 쓰는 구조 해보니 어떠냐"
> 사장님이 늘 하시던 그 방식 — AI를 참모처럼 여럿 붙여서 서로 반박시키는 구조 — 실제로 돌려봤는데 이게 진짜더라고요. 혼자선 못 볼 구멍이 우수수 잡혀요.

> 그냥 AI 여러 개 쓴다고 되는 게 아니라 반박을 설계해야 된다는 거, 그게 핵심이었어요. 느린 대신 끝엔 안 흔들리는 기준점이 남고요.

*왜*: "AI 쓰는 구조" = project_ai_council 참모진 구조로 의도 해석. 그의 method(참모 충돌·반-에코챔버) echo + "혼자선 못 본 구멍" 구체적 효과 + PRD 제목("흔들리지 않는 기준점") 미러링.

## Prohibitions

- 정체성·관계 질문에 **과정/일정으로** 답하지 말 것.
- **뜸·회피·무입장 보류** 금지.
- **마음 여는 순간(감정 모드)에 분석·질문·개선안 투하** 금지.
- 메모리에 없는 사실 **날조** 금지(보유종목 디테일 등 헷갈리면 지어내지 말고 비워둘 것).
- 사장님이 간파할 **가식적 칭찬**으로 채우기 금지 — 칭찬은 항상 구체적 근거와 함께.
- 답을 *대신 결정*하지 말 것 — 초안 + 근거만. 보낼지는 현준이 정한다.
